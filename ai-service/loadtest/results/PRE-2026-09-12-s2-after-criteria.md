# 실행 전 기준: S2 재측정 (5c, anyio 스레드 80)

**이 파일은 숫자를 <보기 전에> 쓴다.** "얼마나 달라야 다른 것인가" 를 결과를 본 뒤에
정하면 그건 판정이 아니라 사후 서술이다. 파도 2 가 `PRE-2026-09-12-identity-criteria.md`
로 남긴 방식을 그대로 따른다.

설계서: `docs/superpowers/specs/2026-09-12-loadtest-pr5-remeasure-design.md` §3 · §5
before: `docs/superpowers/2026-09-10-loadtest-s2-result.md`

---

## 0. 이 판이 답하려는 질문

**anyio 스레드 상한을 40 에서 80 으로 올렸더니 벽이 어디로 옮겨갔는가.**

before 는 40 VU 에서 처리량 천장 **23.9~24.0 req/s** 에 닿았고, 그 값이
`40 스레드 ÷ 1.68초 = 23.8` 과 맞았다. 같은 식으로 새 천장 예측은
`80 ÷ 1.68 = 47.6 req/s` 다.

---

## 1. 사다리와 구간

`1 · 5 · 10 · 20 · 40 · 80 · 160` VU, 단계 유지 120초, **각 단계 앞 20초를 잘라낸 뒤** 집계.
before 의 여섯 칸을 그대로 두고 160 한 칸만 더한다.

- **160 을 더하는 이유**: 새 천장에 닿으려면 동시 요청이 80건은 되어야 하는데
  옛 사다리의 마지막 칸(80 VU)이 새 벽과 <정확히 겹친다>. 80 까지만 돌리면
  선형으로 오르는 것만 보이고 꺾이는지는 못 본다.
- **40 이하를 버리지 않는 이유**: before 에서 선형이었으므로 after 도 선형이어야
  "원래 느렸던 것이 아니다" 를 보일 수 있고, 한 표에 올리려면 같은 칸이 필요하다.

---

## 2. 80 VU 에서의 판정 규칙 (설계서 §3 표를 그대로 옮긴다)

| 80 VU 처리량 | 뜻 | 다음에 볼 것 |
|---|---|---|
| **~47 req/s** (44 이상) | 스레드가 벽이었다. 23.9 → 약 2배 | 160 으로 진행 |
| **24 근처** (26 이하) | 상한이 안 올라갔거나 다른 벽이 이미 있었다 | `alldap_anyio_threads_total` 을 **먼저** 본다 |
| **26 초과 44 미만** | 스레드가 벽이었지만 혼자가 아니었다 | 아래 §4 새 벽 후보 표 |

🔴 **경계 26 과 44 를 지금 정한다.** before 의 천장이 24.0 이고 단계 간 재현 폭이
0.1(24.0 → 23.9)이었으므로, 24 대비 +2 를 "같다고 보지 않는" 선으로 둔다.
44 는 예측치 47.6 의 92% 다. 예측을 정확히 맞히기를 요구하면 어떤 결과도 "예측과
다르다" 가 되므로, "두 배 쪽인가 그대로 쪽인가" 를 가를 수 있을 만큼만 남긴다.

---

## 3. 처리량 천장을 어디로 볼 것인가

**포화의 정의는 before 와 같게 둔다: VU 를 두 배로 올렸는데 처리량이 늘지 않는 것.**
"늘지 않았다" 의 선은 **직전 단계 대비 +5% 미만**으로 정한다
(before 의 40 → 80 이 24.0 → 23.9 로 -0.4% 였다).

---

## 4. 160 이 평평해질 때 무엇이 새 벽인가 (신호를 미리 갈라둔다)

| 후보 | 그것이라는 신호 | 이 판에서 읽는 값 |
|---|---|---|
| anyio 스레드 80 | `alldap_anyio_threads_borrowed` 가 80 에 붙는다 | probe max ≥ 79 |
| **psycopg 풀 10** | `alldap_db_pool_requests_waiting > 0` | probe max > 0 |
| Spring 힙 256m | GC 시간 증가 · OOM · `process_start_time_seconds` 변화 | probe 가 재시작 판정 |
| Tomcat 스레드 200 | `tomcat_threads_busy == 200` | 160 VU 면 안 닿아야 정상 |
| 가짜 CF | 지연이 설정값 합계(1,586ms)보다 커진다 | p50 이 1,586 를 크게 넘는가 |
| **k6 자체** | k6 프로세스 CPU 포화 | probe 의 `k6_cpu_percent` |

psycopg 풀과 k6 는 **before 에 없던 후보다.** before 의 병목 판정에 이 풀은 아예 들어
있지 않았다(후보가 Tomcat · Hikari · anyio 셋뿐. `hikaricp_*` 는 Spring 의 풀이고
이건 Python 의 다른 풀이다).

## 5. 🔴 처리량 0 을 "천장" 으로 읽지 않기 위한 장치

풀이 마르면 30초 대기 → `PoolTimeout` → 500 → Spring 이 Python 5xx 를 서킷 실패로
세어 5건에 30초 차단 → **처리량이 갑자기 0 으로 떨어진다.**
그건 "천장에 닿았다" 가 아니라 **"차단됐다"** 다.

→ **단계별 `alldap_ai_circuit_state` 를 찍는다**(`loadtest/s2_probe.py`).
어느 단계에서든 이 값이 0 이 아닌 표본이 하나라도 있으면, **그 단계의 처리량은
포화 지표로 쓰지 않고 "차단 구간" 으로 따로 적는다.**

`alldap_db_pool_requests_waiting` 도 단계마다 찍는다 — 30초짜리 `PoolTimeout` 대기는
15초 스크레이프 두 번 사이에 통째로 들어갈 수 있어, 포화가 있었는데 그래프에 안 남는
판이 가능하다. probe 간격은 **5초**로 둔다.

## 6. 유효성 장치 (before 의 넷 + 새 넷)

**before 의 넷**
1. fallback **0건**
2. 가짜 CF 호출 배수 **3.0** (기대 3)
3. Spring **재시작 없음**
4. cf-stats `neurons` 가 **전 모델 0.0**

**이 판이 더하는 넷**
5. 🔴 `alldap_anyio_threads_total` **실측 80** — 시작 조건 파일에 **설정값과 따로** 적는다.
   `app/metrics_check.py` ⑤ 는 로컬 `TestClient` 의 lifespan 을 본 것이지 측정 대상
   프로세스를 본 것이 아니다. 실측이 80 이 아니면 이 판은 80 을 잰 것이 아니다.
6. `alldap_db_pool_open == 1` — 0 이면 풀 선 넷이 의미가 없다.
7. 단계별 `alldap_db_pool_requests_waiting` 기록.
8. 단계별 k6 프로세스 CPU 기록.

## 7. 판을 폐기하는 조건 (설계서 §5)

| 조건 | 처분 |
|---|---|
| `alldap_anyio_threads_total != 80` | 폐기 |
| fallback > 0 | 폐기 |
| 가짜 CF 호출 배수 ≠ 3 (±0.05) | 폐기 |
| **OOM 이 아닌** 재시작 | 폐기 |
| **`-XX:+ExitOnOutOfMemoryError` 로 죽은** 재시작 | **폐기가 아니라 결과** — 힙이 새 벽이라는 결론 그 자체 |
| 못 가림 | 무효로 두고 다시 돈다 |

🔴 위 다섯째 줄이 성립하려면 **Spring 에 `-XX:+ExitOnOutOfMemoryError` 가 실제로
붙어 있어야 한다.** 로컬 `bootRun` 기본값에는 없다(파도 2 가 확인했다).
이 판은 `./gradlew bootRun -Ploadtest` 로 띄우고, JVM 플래그를 시작 조건 파일에
`ps` 로 읽은 실제 명령줄에서 적는다.

**k6 CPU 포화는 폐기가 아니다.** 그 단계를 <참고>로만 쓴다. 폐기하면 측정기 문제로
서버 숫자를 전부 버리게 된다.

## 8. 이 판이 하지 않는 것

- 풀 `timeout` 을 바꾸지 않는다. PR #134 가 일부러 보류했다(한 번에 한 변수).
  `waiting > 0` 이 관측되면 **그때 바꿔 한 판 더 돈다.**
- 도구 결함을 고치지 않는다. 5b·5c 를 쪼갠 이유가 <고치지 않은 도구로 재는 것>이다.
  발견하면 고치지 말고 적는다.
- 최종 리포트(`docs/부하테스트-리포트.md`)를 쓰지 않는다. 파도 4 다.
- 미세 탐색(25·30·35 VU)을 하지 않는다. 이 판의 질문은 "벽이 어디로 옮겨갔나" 다.
