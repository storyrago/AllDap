# 경쟁 분석: Chatbase (2026-09-19)

AllDap 과 같은 카테고리(문서 기반 RAG 챗봇 빌더)의 대표 상용 서비스를 조사했다.
비교군으로 Voiceflow · Botpress · CustomGPT.ai 를 같은 축에서 확인했다.

🔴 **읽는 규칙: 이 문서는 <실측>과 <공개 문서>와 <확인 못 함>을 갈라 적는다.**
HTTP 헤더·DNS 를 직접 찔러 확인한 것과, 공식 문서에 적혀 있는 것과, 끝내 확인하지
못한 것은 서로 다른 사실이다. 2차 출처(블로그·비교글)는 출처로 쓰지 않았고,
쓴 자리는 그렇다고 명시했다.

---

## 1. 결론 세 줄

1. **Chatbase 는 같은 제품이 아니라 훨씬 넓고 얕은 제품이다.** AllDap 과 겹치는 것
   (문서 업로드 → RAG → 위젯)은 그쪽 기능의 일부이고, 채널 15종 · 액션(툴 호출) ·
   데이터 소스 6종이 더 있다.
2. **그런데 깊이 판 축이 반대다.** Chatbase 는 답변 품질을 <무엇으로 재는지 공개조차
   하지 않는다>. 빌더 제품 중 사전 테스트 세트로 회귀 측정을 하는 곳을 이번 조사에서
   찾지 못했다.
3. 🔴 **기술 스택은 TypeScript 단일이다. Python 서비스가 없다.** ARR $10M · 엔지니어
   11명이 그렇게 하고 있다. AllDap 의 3-서비스 구조와 정면으로 갈리는 지점이고,
   이것은 AllDap 이 이미 "알고 택했다" 고 적어둔 것의 <바깥 근거>가 된다(§6).

## 2. 기술 스택 (실측)

DNS 와 HTTP 응답 헤더를 직접 확인한 것이다. 2026-09-19 기준.

| 구성요소 | 확인된 값 | 근거 |
|---|---|---|
| 웹앱 | **Next.js App Router / Vercel** | `server: Vercel` · `x-nextjs-prerender: 1` · `vary: rsc, next-router-state-tree` · HTML 에 `_next/static/immutable/chunks/*.js` |
| 대시보드 가드 | 같은 Next.js 앱 안 | `GET /dashboard` → `307` + `location: /auth/signin?next=%2Fdashboard` |
| 위젯 | `embed.min.js` (49KB), Vercel 서빙 | `x-matched-path: /embed.min.js` |
| 위젯 구조 | **iframe** | 스크립트 내부 문자열 `"/chatbot-iframe/"` · `"/api/get-chatbot-styles/"` · `"/api/embed/extended-scripts/"` · `"/api/geo"` |
| iframe 페이지 | Next.js 동적 라우트 | `GET /chatbot-iframe/test` → `x-matched-path: /chatbot-iframe/[chatbotId]` |
| 데이터 계층 | **Supabase** (커스텀 도메인) | `backend.chatbase.co` → `cpjvqaqlborhtxjycmgd.supabase.co`. `/rest/v1/`·`/auth/v1/*` → 401 + `sb-project-ref` 헤더. Storage · Edge Functions 응답 확인 |
| 별도 API | **Node.js Express / Railway** | `api.chatbase.co` → `5l7a9pd6.up.railway.app`. `x-powered-by: Express` · `server: railway-hikari` |
| **Python 흔적** | **없음** | `api.chatbase.co/docs` · `/openapi.json` 둘 다 Express 404 HTML. FastAPI 였다면 Swagger 가 떴을 자리다 |
| 부가 | Cloudflare(Supabase 앞단) · Stripe · Cloudflare Turnstile | CSP 에 `js.stripe.com` · `challenges.cloudflare.com` |

**벡터 저장소: Pinecone → pgvector 로 <이전했다>** (Supabase 공식 고객 사례).

- 이전 이유가 성능이 아니라 **운영 단순화**다. 창업자 Yasser Elsaid 인용:
  *"Instead of splitting things out as we go, we try to consolidate things more as we do."*
- 구체적 이득으로 **cascade delete** 를 든다. 문서·에이전트를 지우면 임베딩이 FK 로
  함께 지워져 벤더 간 수동 동기화가 없어진다.
- 분석 워크로드(Metabase)를 올렸다가 **3,000 IOPS · 125 MB/s** 천장을 만났다고 언급.

**모델 선택을 사용자에게 노출한다.** 메시지당 크레딧이 모델마다 다르다.

## 4. 품질 평가 기능 — 여기가 갈리는 지점

| 제품 | 평가 기능 | 그 자리에 있는 것 |
|---|---|---|
| **Chatbase** | **없음** (확인) | Analytics 4탭: Chats(대화수·메시지수·엄지척/아래·DAU) · Topics · Sentiment · Helpdesk. 전부 "얼마나 쓰였나" 이고 "맞았나" 가 아니다 |
| Chatbase | 대신 **Revise Answer** | 사람이 대화 로그에서 답을 손으로 고치면 Q&A 데이터로 저장돼 다음 질의에 쓰인다. **측정이 아니라 수동 교정** |
| **Voiceflow** | **있음 (LLM-as-judge)** | Evaluations: 고객이 정의한 criteria 로 모델이 **transcript 전문**을 읽고 점수+근거. metric 4종(Rating·Binary·Options·Text). 기본 3종: customer satisfaction · deflection rate · resolution rate |
| CustomGPT.ai | 없음 (고객 화면 기준) | "LLM-agent 로 quality score 계산" 은 **내부 프로세스 서술**이고, 고객이 테스트셋을 돌려 점수를 보는 화면은 없다 |
| Botpress · SiteGPT · Dante AI | **확인 못 함** | 공식 문서 전수 확인 실패. "없다" 가 아니라 "못 봤다" |

**Voiceflow 와 AllDap 의 실제 차이 (이게 핵심이다)**

| | Voiceflow Evaluations | AllDap |
|---|---|---|
| 채점 입력 | **실제 대화 transcript** (사후·상시) | **고정된 테스트 질문 세트** (사전·반복) |
| 질문 출처 | 진짜 사용자 | LLM 이 청크에서 (질문, 정답) 쌍 생성 |
| 기준 | 고객이 자연어로 criteria 작성 | 충실성·관련성·응답률 고정 지표 |
| 성격 | CX 품질 모니터링 | **RAG 파이프라인 회귀 측정 (설정 A vs B)** |

🔴 **대화 로그는 매번 다른 질문이라 설정 A 와 B 를 비교할 수 없다.** 같은 질문 세트를
고정하고 설정마다 3회씩 돌려 편차까지 보는 구조는 이번 조사 범위에서 찾지 못했다.

**업계 구도는 가설대로다.** Ragas · LangSmith · Braintrust · Arize Phoenix 는
SDK · 트레이싱 · CI 기반의 **개발자용 별도 카테고리**이고 노코드 빌더에 붙어 있지 않다.
예외가 Voiceflow 이고, 그것도 지표 정의가 자연어라 Ragas 식 표준 지표 세트와 다르다.

**지표 이름 관행 (AllDap 용어 검증)**

| 이름 | 통용되는가 |
|---|---|
| `faithfulness` | ✅ Ragas 공식 지표명 그대로 |
| `answer relevancy` | ⚠️ 현행 Ragas 는 **`response relevancy`** 로 개명. 구명칭이자 통용어 |
| `groundedness` | ✅ 통용. faithfulness 와 실무에서 거의 호환 |
| `context precision / recall` | ✅ Ragas 공식 |

→ **AllDap 의 표기는 맞다.** 영문으로 쓸 때만 `response relevancy` 가 현행과 일치한다.

**환각 억제**: Chatbase 는 **"AI-powered guardrails"** 라는 표현과 시스템 프롬프트
예시("환불은 다루지 말고 사람에게 넘겨")까지다. 즉 **프롬프트로 막는다.**
"근거 없으면 답하지 않는다" 를 코드 레벨 장치로 내세우는 기능명은 확인 못 했다.

## 5. 🔴 확인 못 한 것 (추측하지 않는다)

- **Chatbase 가 출처(citation)를 표시하는가.** 공식 홈 · docs · llm-info 어디에서도
  citation / source attribution 을 기능으로 명시한 문장을 찾지 못했다. 2차 출처들은
  일반 RAG 설명 투로만 언급한다.
  🔴 **AllDap 한 줄 소개의 첫 단어가 "출처가 표시되는" 이라 이건 닫아야 한다.**
  닫는 방법: 계정을 만들어 답변 UI 를 직접 본다.
- **Voiceflow 의 Test Platform (experimental).** 문서 링크는 존재하나 리다이렉트로
  본문 확보 실패. **시뮬레이션 기반 <사전> 테스트일 가능성**이 있고, 그렇다면 §4 의
  차별점 서술이 약해진다. 차별점을 자소서·면접에서 주장하기 전에 확인할 것.
- Chatbase 텍스트 챗의 fallback 메시지 설정 기능 유무 (음성 쪽 "Error Message" 만 확인).
- Chatbase 의 임베딩 모델 · 청킹 · 리랭킹 전략. `api.chatbase.co`(Express)가 하는 일.
  경로가 전부 인증 뒤라 확인 불가.
- LangChain 사용 여부. 2023년 기사들이 언급하나 현재 근거 없음.
- **엔지니어링 채용공고에서 스택을 뽑는 데 실패했다.** Ashby 보드에 열린 3건이 전부
  GTM·마케팅이고 엔지니어링 0건. 과거 공고 아카이브도 못 찾았다.
- Chatbase 의 "Suggestions"(지식 공백 탐지, Pro 전용): 경쟁사 리뷰 글에만 나오고
  공식 문서에서 확인 못 함.
- Botpress · SiteGPT · Dante AI 의 평가 기능 유무.

## 6. 면접에서 쓸 각도

**① 3-서비스 구조를 "알고 택했다" 의 바깥 근거가 생겼다.**
`AGENTS.md` 가 이미 *"배포 대상 3개는 PRD §11.2 원칙과 충돌하는 걸 알고 택했다"* 고
적어뒀다. 여기에 사실이 하나 붙는다: **이 시장에서 ARR $10M 을 내는 회사가
엔지니어 11명으로 TypeScript 단일 스택을 쓴다.** Python 서비스가 없다.
→ *"AI 파이프라인에 Python 이 필수는 아니라는 걸 상용 레퍼런스가 보여줍니다.
그럼에도 나눈 이유는 채용공고 8건 중 6건이 Java/Spring 을 요구했고, 이 프로젝트의
1순위 목적이 포트폴리오이기 때문입니다."*
🔴 **몰라서 어긴 것과 알고 택한 것의 차이가 여기서 증명된다.**

**② 벡터 선택이 같은 결론에 도달했다.**
그쪽은 Pinecone 을 써보고 pgvector 로 돌아왔고, 이유가 성능이 아니라 cascade delete 와
벤더 단일화였다. AllDap 의 *"공유 DB 는 안티패턴이지만 1인 개발에서 동기화 비용이
분리 이득보다 크다"* 와 **논리 구조가 같다.** 남의 사례로 뒷받침할 수 있다.

**③ 모델 선택 노출이 갈린다.**
Chatbase 는 8종을 고르게 하고 크레딧으로 과금한다. AllDap 은 고정이되
**생성(Meta 계열)과 채점(Mistral 계열)을 일부러 갈랐다** (자기 채점 방지).
사용자가 모델을 고르면 두 계열이 겹칠 수 있고 그러면 품질 측정이 무너진다.
→ **측정 가능성을 위해 선택지를 포기한 설계**이고, Chatbase 공개 자료에 대응물이 없다.

**④ 환각 억제가 프롬프트가 아니라 코드다.**
Chatbase 는 마케팅 문구와 시스템 프롬프트 예시까지다. AllDap 은 `max_distance`
검색컷이 코드에 있고, 심지어 **프롬프트 방어선(`NO_ANSWER`)은 봇 설정 한 줄로 뚫린다는
것을 `bot_prompt_check` 로 실측해 문서화**해 뒀다.

**⑤ HWPX 를 읽는다.** Chatbase 지원 형식은 `.pdf .txt .doc .docx` 뿐이다.

**⑥ 그들이 공개하지 않은 것이 차별점이다.**
Chatbase 에 eval 파이프라인 공개 언급이 0건이다.
→ *"상용 서비스도 답변 품질을 무엇으로 재는지 공개하지 않는데, 저는 그걸 제품의
일부로 만들었고 그 채점자가 믿을 만한지까지 사람 라벨과 대조해 쟀습니다."*
