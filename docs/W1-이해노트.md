## 1단계. 큰 그림 — 이 봇은 사서다

누가 질문하면 사서가 이렇게 합니다.

```
① 책을 미리 잘라서 정리해둔다      ← 문서를 올릴 때 (한 번)
② 질문이 오면 관련 페이지를 찾는다   ← 질문할 때
③ 그 페이지만 보고 답을 쓴다        ← 질문할 때
```

**핵심은 ③의 "그 페이지만 보고"입니다.**

사서가 자기 기억으로 답하면 그럴듯한 거짓말이 나옵니다. 그게 **환각(hallucination)**이고,
이 제품이 존재하는 이유가 그걸 막는 것입니다.

### 4문항은 이 3단계에 하나씩 붙어 있다

| 문항 | 단계 | 한 줄 요약 |
|---|---|---|
| **3. 겹침(overlap)** | ① 자를 때 | 페이지를 자르면 문장이 중간에 끊기니까 **조금 겹치게** 자른다 |
| **4. HWPX 병합** | ① 자를 때 | 한글 파일은 글자가 잘게 쪼개져 있어서 **도로 붙여야** 문장이 된다 |
| **2. max_distance** | ② 찾을 때 | 엉뚱한 페이지를 찾아왔으면 **아예 안 보여준다** |
| **1. NO_ANSWER** | ③ 쓸 때 | 페이지에 없으면 지어내지 말고 **"모른다"고 하게** 시킨다 |

### 왜 1번과 2번이 둘 다 있나 (2중 방어)

막는 실패가 서로 다르기 때문입니다.

| 방어선 | 막는 것 |
|---|---|
| **2. max_distance** (찾을 때) | 애초에 **문서에 없는** 질문 → 엉뚱한 자료를 아예 안 준다 |
| **1. NO_ANSWER** (쓸 때) | 자료는 줬는데 **그걸로는 답이 안 되는** 질문 → 모른다고 말하게 한다 |

## 2단계. 각각 왜 필요한가

### 3. 겹침(overlap) — 문장이 잘리는 문제

문서를 그냥 500자씩 툭툭 자르면 이런 일이 생깁니다.

```
...휴학은 매 학기 개시일로부터 30일 이내에 신청해야 한다.
━━━━━━━━━━━━━━ 여기서 잘림 ━━━━━━━━━━━━━━
단, 군휴학은 이에 산입하지 않는다.
```

이제 **"군휴학도 30일 안에 신청해야 하나요?"** 라고 물어보면:

- **뒷조각만 찾아오면** → "단, 군휴학은 이에 산입하지 않는다" 만 보임.
  **무엇에** 산입하지 않는다는 건지 알 수가 없음
- **앞조각만 찾아오면** → 예외 조항이 있다는 걸 아예 모름

**해결**: 뒷조각이 앞조각의 **마지막 50자를 물고 시작**하게 합니다.
그러면 경계 근처 내용이 양쪽에 다 들어가서, 어느 쪽이 검색돼도 문맥이 살아 있습니다.

**공짜가 아님** — 겹치는 만큼 저장 공간과 임베딩 비용이 늘고, 같은 내용이 두 군데
있으니 검색 결과에 중복이 뜰 수 있습니다. 그래서 `500자에 50자(10%)`.
이 비율은 **근거 있는 값이 아니라 시작점**이고, W4에서 바꿔가며 점수로 비교할 대상입니다.

---

### 4. HWPX 병합 — 한 문장이 조각나는 문제

HWPX(한글 파일)는 압축을 풀면 XML입니다. 그런데 **서식이 바뀌는 지점마다 텍스트가 쪼개져 있습니다.**

```
파일 안에 이렇게 저장돼 있음:

   [휴학은 ]  [30일]  [ 이내에 신청한다.]
              ↑ 여기만 굵게 했더니 따로 떨어짐
```

**글자 하나만 굵게 해도 거기서 갈립니다.** 색을 바꿔도 그렇고,
편집을 여러 번 하면 서식이 같은데도 갈려 있는 경우가 있습니다.

이걸 그대로 읽어서 줄바꿈으로 이으면:

```
휴학은
30일
이내에 신청한다.
```

**문장이 아닙니다.** 이 상태로 ①번(자르기)을 하면 조각들이 따로 놀고,
검색용으로 만드는 숫자(임베딩)도 의미 없는 파편의 숫자가 되고, 검색이 망가집니다.

**해결**: **문단 단위로 묶어서, 조각들을 구분자 없이 그냥 이어붙입니다.**
줄바꿈으로 이으면 안 됩니다 — 그럼 위 문제가 그대로 남습니다.

### 2. max_distance — 검색이 항상 뭔가를 돌려주는 문제

**벡터 검색은 관련이 없어도 무조건 `top_k`개(기본 5개)를 돌려줍니다.**

*"오늘 점심 뭐 먹지"* 라고 물어도 학사 규정 조각 5개가 나옵니다.
**"가장 덜 관련 없는" 것**을 주는 거지, "관련 있는 것"을 주는 게 아닙니다.

그 5개를 그대로 AI에게 넘기면 — AI는 *"이게 근거다"* 라고 받았으니 어떻게든 엮어보려 합니다.
③단계에서 "모르면 모른다고 해"라고 시켜놔도, 눈앞에 자료가 있으면 흔들립니다.

**해결**: 검색 결과에 **"얼마나 비슷한지" 점수가 함께 나옵니다.**
그 점수가 기준(`max_distance`)보다 나쁘면 버립니다.

**한 장치로 두 가지를 얻습니다:**

| | |
|---|---|
| 환각 억제 **1차 방어선** | 무관한 자료를 AI에게 아예 안 보여줌 |
| **비용 절감** | 남은 자료가 하나도 없으면 **AI를 호출조차 안 함** |

두 번째가 중요합니다. 문서에 없는 질문은 **AI 요금이 0원**입니다.

**알아야 할 약점** — `0.55`라는 기준값은 **근거 없이 정한 숫자**입니다.
너무 낮으면 답할 수 있는 것도 "모른다"가 되고, 너무 높으면 환각이 납니다.
W4에서 이 값을 바꿔가며 평가 점수로 비교하는 게 계획이고, 그게 **before/after 비교표의 재료**입니다.

### 1. NO_ANSWER — "모른다"를 기계가 알아들어야 하는 문제

AI는 기본적으로 **답을 만들어내는** 기계입니다. 모른다고 말하는 게 기본값이 아닙니다.

그래서 프롬프트에 이렇게 적어뒀습니다:

> 문서에서 답을 찾을 수 없으면, 추측하지 말고 정확히 이렇게만 답하세요: **"NO_ANSWER"**

**왜 "모르면 모른다고 해"가 아니라 정해진 단어인가 — 여기가 핵심입니다.**

그냥 시키면 AI는 이렇게 답합니다:

```
"죄송하지만 제공된 문서에서는 해당 내용을 찾을 수 없습니다."
"문서에 관련 정보가 없어 답변드리기 어렵습니다."
"해당 사항은 문서에 명시되어 있지 않습니다."
```

**전부 맞는 답인데, 매번 표현이 다릅니다.** 사람은 알아보지만 **프로그램은 못 알아봅니다.**

`NO_ANSWER`라는 정해진 단어 하나면 프로그램이 딱 판정할 수 있고, 그 판정이 이렇게 이어집니다:

```
NO_ANSWER 감지
  → 이 답변은 "못 답한 것"으로 기록  (is_fallback = true)
  → 미답변률 집계
  → W3 품질 대시보드에 숫자로 표시
  → 못 답한 질문에는 요금 안 받음  (PRD §13.1 과금축)
```

**즉 환각을 막는 것만이 목적이 아니라, 막았는지 "셀 수 있게" 만드는 게 목적입니다.**
이 프로젝트의 차별점이 "품질을 숫자로 증명한다"인데, 그 숫자가 여기서 시작됩니다.

## 3단계. 코드로 확인하기

> 여기부터는 실제 코드입니다. 2단계가 이해됐을 때 보세요.

### 1. NO_ANSWER — `app/generator.py`

```python
FALLBACK_TOKEN = "NO_ANSWER"

# ... AI 응답을 받은 뒤 ...
if FALLBACK_TOKEN in answer or not answer:
    return fallback_message, True     # True = is_fallback
```

**Python 문법**

- `==` 이 아니라 `in` 입니다. AI가 `"NO_ANSWER입니다"` 처럼 앞뒤에 뭘 붙여도 잡힙니다
- `not answer` — Python에서 **빈 문자열은 거짓**입니다. 응답이 비어도 fallback 처리

```python
answer = "".join(
    block.text for block in resp.content if getattr(block, "type", None) == "text"
).strip()
```

- AI 응답의 `content`는 **여러 블록이 담긴 리스트**입니다. 텍스트 말고 다른 종류가 섞일 수 있어
  `type == "text"` 인 것만 골라냅니다
- 괄호 안의 `for ... if ...` 는 **제너레이터 표현식**. 리스트를 따로 만들지 않고
  하나씩 흘려보내면서 `join`으로 이어붙입니다
- `getattr(block, "type", None)` — 속성이 없으면 예외 대신 `None`을 줍니다.
  `block.type` 이라고 쓰면 그 속성이 없는 블록에서 프로그램이 죽습니다

### 2. max_distance — `app/retriever.py`

```python
sql = """
    SELECT c.id, c.document_id, d.filename, c.content,
           c.embedding <=> %s::vector AS distance
    FROM chunks c
    JOIN documents d ON d.id = c.document_id
    WHERE c.bot_id = %s AND c.embedding IS NOT NULL
    ORDER BY distance
    LIMIT %s
"""
# ...
for chunk_id, doc_id, filename, content, distance in rows:
    if distance > max_distance:
        continue          # ← 기준보다 먼 건 버린다
```

**문법**

- `<=>` 는 **pgvector의 코사인 거리 연산자**입니다. **0에 가까울수록 비슷**합니다
- `ORDER BY distance LIMIT 5` — 이 쿼리는 **무조건 5개를 돌려줍니다.**
  그래서 파이썬 쪽에서 한 번 더 걸러야 하는 것입니다
- `%s::vector` — PostgreSQL 타입 변환. 파이썬 리스트를 벡터 타입으로 명시

```python
score=round(1.0 - float(distance), 4)
```

- 거리를 **점수로 뒤집어서** 화면에 보냅니다. 사용자에겐 "관련도 92%"가
  "거리 0.08"보다 직관적이니까요
- `float()`로 감싼 이유: DB 드라이버가 숫자를 `Decimal` 타입으로 줄 수 있는데,
  `Decimal`과 `float`를 섞어서 계산하면 에러가 납니다

**그리고 `app/generator.py` 맨 앞:**

```python
# 검색 단계에서 이미 걸러졌다면 LLM을 부를 필요도 없다 (비용 절감)
if not sources:
    return fallback_message, True
```

남은 자료가 없으면 **여기서 끝납니다. AI 호출 없음 = 요금 0원.**

### 3. 겹침(overlap) — `app/chunker.py`

```python
if len(candidate) > size and buf:
    chunks.append(buf)
    tail = buf[-overlap:] if overlap else ""        # ← 앞 조각의 꼬리 50자
    buf = f"{tail}\n{piece}".strip() if tail else piece
```

**Python 문법**

- `buf[-overlap:]` 는 **음수 슬라이싱**. 뒤에서부터 50자를 잘라냅니다
- 문자열이 50자보다 짧아도 **에러가 안 납니다.** 그냥 있는 만큼 줍니다.
  그래서 길이 검사를 따로 안 해도 됩니다
- `A if 조건 else B` 는 **조건부 표현식**(다른 언어의 삼항 연산자)

```python
def chunk_text(text: str, *, size: int = 500, overlap: int = 50):
```

- `*` 뒤의 인자는 **키워드로만** 넘길 수 있습니다. `chunk_text(t, 500, 50)` 은 에러
- 왜 이렇게? — `chunk_text(text, size=800, overlap=100)` 은 호출부만 봐도 뜻이 읽힙니다.
  `chunk_text(text, 800, 100)` 은 **뭐가 뭔지 모릅니다**
- 파일 상단 주석의 *"W4에서 파라미터를 바꿔가며 비교할 예정이므로 바깥에서 주입받도록
  열어둔다"* 가 이 얘기입니다

### 4. HWPX 병합 — `app/parsers.py`

```python
_HWPX_TEXT_TAG = "}t"     # 네임스페이스 무시하고 로컬명으로 비교
_HWPX_PARA_TAG = "}p"

for para in root.iter():
    if not para.tag.endswith(_HWPX_PARA_TAG):    # 문단(<hp:p>)만
        continue
    buf = [node.text for node in para.iter()
           if node.tag.endswith(_HWPX_TEXT_TAG) and node.text]
    line = "".join(buf).strip()                  # ← 구분자 없이 이어붙임
```

**`"".join(buf)` 이 이 코드의 핵심입니다.** `"\n".join` 이었으면 문장이 조각난 채로 남습니다.

**문법 — 왜 `"hp:t"` 가 아니라 `"}t"` 인가 (제일 헷갈리는 부분)**

파일에는 `<hp:t>` 라고 써 있지만, Python의 XML 파서는 **네임스페이스를 URL로 확장**합니다.
파싱하고 나면 태그 이름이 이렇게 됩니다:

```
{http://www.hancom.co.kr/hwpml/2011/paragraph}t
```

`hp:` 라는 접두사는 사라지고 URL이 앞에 붙습니다.
그런데 **그 URL은 HWPX 버전에 따라 달라질 수 있습니다.**
그래서 URL은 무시하고 `}t` 로 끝나는지만 봅니다 — 네임스페이스와 무관하게 **로컬명만 비교**하는 관용구입니다.

- `and node.text` — `<hp:t/>` 처럼 빈 요소면 `node.text` 가 `None` 입니다.
  그대로 `"".join` 에 넣으면 에러가 나서 미리 거릅니다
- `para.iter()` — 그 아래 **모든 자손**을 훑습니다. 조각이 깊이 중첩돼 있어도 잡힙니다

> **용어 정정**: `AGENTS.md` 에는 `<hp:run>` 으로 적혀 있는데 코드는 `<hp:t>` 단위로 모읍니다.
> `<hp:run>` 은 *서식이 같은 구간*이고 그 안의 실제 글자가 `<hp:t>` 입니다.
> 결과적으로 run 을 합치는 것과 같습니다.

## 4단계. 네 개가 사실 하나의 이야기다

```
[3] 겹침       ┐
                ├─  검색이 제대로 되게 만드는 준비
[4] HWPX 병합  ┘

[2] max_distance  ┐
                   ├─  검색이 실패했을 때 지어내지 않게 하는 방어
[1] NO_ANSWER     ┘
```

**3·4를 소홀히 하면 2·1이 과하게 발동합니다.**
문맥이 끊기고 문장이 파편화되면 → 검색 점수가 나빠지고 → `max_distance` 에 걸려서
→ **답할 수 있는 질문까지 "모른다"** 가 됩니다. 미답변률이 올라가죠.

**반대로 2·1이 없으면 3·4가 아무리 좋아도 환각이 납니다.**

> "벡터 검색은 관련이 없어도 top_k개를 무조건 돌려줍니다. 그걸 그대로 근거로 주면
> 모델이 억지로 엮어서 답해요. 그래서 임계치로 먼저 거르고, 거를 게 없으면 LLM을
> 호출하지도 않습니다 — **환각 방어와 비용 절감이 같은 장치에서** 나옵니다.
> 임계값 자체는 아직 근거 없는 가정값이라 W4에서 평가 점수로 튜닝할 계획입니다."

**3. 겹침**
> "경계에서 문맥이 끊기는 걸 막으려고요. '단, 군휴학은 산입하지 않는다'만 검색되면
> 무엇에 산입하지 않는지 모르니까, 뒤 조각이 앞 조각 꼬리를 물고 시작하게 했습니다.
> 대신 저장·임베딩 비용이 겹치는 만큼 늘어서 500자에 50자로 잡았고,
> 이 비율도 W4에서 조정할 값입니다."

**4. HWPX**
> "HWPX는 서식이 바뀌는 지점마다 텍스트를 여러 조각으로 쪼개둡니다. 단어 하나만 굵게 해도
> 거기서 갈려요. 그대로 읽으면 한 문장이 세 조각으로 나와서 청킹도 임베딩도 다 망가집니다.
> 그래서 문단 단위로 묶어 **구분자 없이** 이어붙였습니다."
