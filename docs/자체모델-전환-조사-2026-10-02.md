# 자체 모델 전환 조사 (2026-10-02)

이 문서는 결정이 아니라 조사 기록이다. 무엇을 바꿀지는 사용자가 정한다(7절).

## 1. 왜 조사했나

AllDap 은 임베딩, 답변 생성, 채점을 Cloudflare Workers AI 가 돌려 주는 모델로 처리한다. 사용자는 앞으로 이 모델들 대신 직접 고른 모델을 직접 돌리는 쪽을 검토하려 한다. 리랭커 파인튜닝 실험이 2026-10-02 에 학습 전 관문에서 종료된 뒤 나온 방향이다(결과: [`superpowers/plans/2026-10-01-reranker-finetune-results.md`](superpowers/plans/2026-10-01-reranker-finetune-results.md). 이 파일은 PR #156 이 머지되면 `main` 에 생긴다).

## 2. 먼저 짚어 둘 사실

**Cloudflare 는 모델을 만드는 곳이 아니라, 공개된 모델을 대신 돌려 주는 곳이다.** 지금 쓰는 모델의 출처는 이렇다.

| 용도 | 모델 | 만든 곳 |
|---|---|---|
| 임베딩 | `bge-m3` | BAAI |
| 리랭커 | `bge-reranker-base` | BAAI (이미 로컬에서도 돌린다) |
| 답변 생성 | `llama-3.3-70b-instruct` | Meta |
| 채점 | `mistral-small-3.1-24b-instruct` | Mistral |

넷 다 Hugging Face 에 가중치가 공개돼 있다. 따라서 "직접 쓴다" 는 같은 모델이나 다른 공개 모델을 받아 우리 장비에서 돌리는 것이다. 모델을 처음부터 학습시키는 것이 아니다.

## 3. 용량: 맥북에 들어가는가

장비는 맥북 M4 Pro, 메모리 24GB 다. 운영체제와 다른 프로그램을 빼면 모델에 쓸 수 있는 몫은 대략 16~18GB 로 추정한다.

모델이 차지하는 메모리는 대략 **파라미터 수 × 파라미터당 바이트**다. fp16 이면 2바이트, 4비트 양자화면 약 0.5바이트다(실행에 드는 여분은 따로 붙는다).

| 용도 | 모델 크기 | 어림 메모리 | 판단 |
|---|---|---|---|
| 리랭커 | 약 2억 7천만 | INT8 약 0.3GB | 가능 (이미 돌린다) |
| 임베딩 | 약 5억 7천만 (`bge-m3`) | fp16 약 1.1GB | 가능 |
| 채점 | 240억 | 4비트 약 14GB | 빠듯하다 |
| 답변 생성 | 700억 | 4비트 약 40GB | 불가능 |

- 답변 생성은 70B 를 그대로 옮길 수 없고, 7~14B 급(4비트 약 5~9GB)으로 바꿔야 한다. 이때 위험은 "문서에 근거가 없으면 `NO_ANSWER` 라고만 답하라" 는 지시를 지키는가다. 이전에 `qwen3-30b-a3b` 가 이 지시를 0/3 으로 지키지 못해 탈락했다(`ai-service/app/config.py` 의 모델 선택 주석). 작은 모델일수록 더 위험하다고 봐야 한다.
- 운영 서버(EC2)는 메모리가 1GB 라 어느 모델도 직접 돌릴 수 없다.
- **위 수치는 전부 어림 계산이다. 실제로 올려서 재지 않았다.**

## 4. 다른 개인 프로젝트는 어떻게 하나 (2026-10-02 웹 검색)

**대개 Ollama 로 공개 모델을 받아 그대로 돌린다.** `bge-m3` 임베딩에 qwen 계열 7~8B 생성 모델을 붙이는 조합이 흔하다. 파인튜닝까지 하는 경우는 드물다.

- [straycat405/personal-llm](https://github.com/straycat405/personal-llm): VRAM 8GB PC 에서 `qwen3:8b` 와 `bge-m3` 를 돌린다.
- [geonhoa3/company-policy-rag](https://github.com/geonhoa3/company-policy-rag): 사내 취업규칙 RAG. `bge-m3` 와 `qwen2.5:7b` 를 쓰고, 유사도가 0.5 미만이면 모른다고 답한다. **AllDap 과 주제가 거의 같다.**

**채점 전용 공개 모델도 있다.**

- Prometheus 2: [논문](https://huggingface.co/papers/2405.01535)
- 다국어판 M-Prometheus (3B~14B): [논문](https://arxiv.org/pdf/2504.04953)

**API 와 직접 돌리기를 비교하면**, 직접 돌리는 7~8B 모델은 품질 상한이 낮은 대신 문서가 밖으로 나가지 않고 호출당 비용이 0 이다. 일상적인 작업은 로컬 모델로, 어려운 추론은 API 로 섞어 쓰는 방식이 흔하다. 비용만 놓고 보면 하루 수백만 토큰 이상을 써야 직접 돌리는 쪽이 싸다는 분석이 있다.

- [daily.dev: Running LLMs locally](https://daily.dev/blog/running-llms-locally-ollama-llama-cpp-self-hosted-ai-developers/)
- [Digital Applied: Self-hosting open-weight LLMs 2026](https://www.digitalapplied.com/blog/self-hosting-open-weight-llms-2026-deployment-decision-guide)

**이 절은 검색 결과를 요약한 것이다. 글에 나온 수치를 직접 검증하지 않았다.**

## 5. AllDap 에 주는 함의

- **직접 돌리는 것 자체는 차별점이 아니다.** 같은 주제를 로컬 모델로 만든 공개 저장소가 이미 있다(4절).
- **차별점은 바꾼 뒤 재서 증명하는 것이다.** AllDap 에는 이미 잴 자가 있다.
  - 채점: 사람이 매긴 라벨 44건. 지금 채점 모델과의 일치율 90.9%(2026-09-25, [`실측-기록.md`](실측-기록.md) 의 채점자 대조 절)
  - 답변 생성: 근거 없는 질문에 지어내지 않는지 보는 fallback 테스트
  - 리랭커: 파인튜닝 실험에서 만든 시험 문제 71개(로컬 시험용 봇 8번). 원본 모델이 64/71 을 정답 근거 5개 안에 넣는다. 새 리랭커가 이보다 나빠지지 않는지 보는 기준선으로 쓴다
- **배포는 섞어 쓰는 것이 현실적이다.** 실제 서비스는 지금처럼 API 를 쓰고, 실험과 평가는 로컬 모델로 돌린다. 당분간 로컬에서만 개발한다는 2026-10-01 결정과도 맞는다.

## 6. 추천 순서와 첫 후보 (결정 아님)

**채점 → 임베딩 → 답변 생성** 순서를 추천한다. 리랭커는 이미 로컬 경로가 있어 순서에서 뺐다.

첫 후보는 **채점 모델을 M-Prometheus 같은 공개 채점 모델로 바꾸고, 사람 라벨 44건으로 지금 채점 모델과 비교하는 것**이다. 이유는 셋이다.

- 4비트로 맥북에 들어간다(3B~14B).
- 비용이 가장 큰 자리다. 평가 1회(16문항) 804 뉴런 중 채점이 410 뉴런으로 약 51% 를 차지한다([`실측-기록.md`](실측-기록.md) 의 회당 비용 절). Cloudflare 무료 한도는 하루 10,000 뉴런이다.
- 잴 자(사람 라벨 44건)가 이미 있다.

## 7. 열린 결정

AGENTS.md 작업 규칙 7번은 지금 리랭커 추론만 로컬에서 돌리도록 허용한다. 채점, 임베딩, 답변 생성으로 넓히려면 **사용자가 그 규칙을 여는 결정**이 먼저 필요하다. 이 문서는 그 결정을 위한 재료다.
