# 코퍼스 중복 규정 감사 (2026-09-18)

`ai-service/testdata/corpus/` 의 문서들이 **같은 규정을 여러 번 적고 있다.**
그 쌍을 전부 찾아 목록으로 만든 것이 이 문서다.

🔴 **이 감사는 50문서 · 306청크 기준이고, 2026-09-18 에 코퍼스에 문서 6개가 추가됐다
(50 → 56). 새 문서 6개는 이 감사에 포함되지 않았다.** 아래의 모든 개수와 목록은
50문서 시점의 것이다. 새 문서를 포함한 재조사는 별도 작업이며, 아래 §7 의 명령을
그대로 다시 돌리면 된다.

## 왜 남기는가

두 번 실제로 작용했기 때문이다.

1. 2026-09-18 에 난이도 문항을 만들면서 **생성기가 낸 후보 16개 중 4개가
   정답 청크의 쌍둥이 때문에 못 쓰게 됐다** (재택근무 주2회 · 식대 월 15만원 ·
   장비 노트북 · 퇴직금 1년).
2. 그러다 **기존 평가셋 30문항 중 4문항이 이미 오염돼 있다**는 것이 드러났다 (§4).

🔴 **왜 치명적인가**: 쌍둥이가 top5 에 들어오면 봇의 답은 맞는데 `rank_trace` 는
"정답 청크가 근거에 없다"(판정 ②)고 말한다. 그 판정 개수가 "리랭커를 고칠 여지가
있는가" 의 근거 자체라, 오염되면 **다음 슬라이스의 방향을 잘못 정하게 된다.**

## 어떻게 쟀는가

| | |
|---|---|
| 대상 | `ai-service/testdata/corpus/` 50문서 → 306청크 (chunk_size=500 · overlap=50 · split_headings=True) |
| 도구 | 표준 라이브러리 `difflib.SequenceMatcher` 만 |
| 안 쓴 것 | DB · 임베딩 · 외부 API. 평가를 돌리지 않았다 |
| 비교량 | 문장 670개, 서로 다른 청크에 속한 조합 223,468쌍 전수 |

**청크 통째 유사도는 못 쓴다.** `08_징계_및_고충처리#2 ↔ 취업규칙#10` 은 문장 하나가
`r=0.988` 로 사실상 동일한데 **청크 통째로는 0.353** 이다. 청크 하나에 조항이 여럿
들어 있어 나머지 문장이 유사도를 희석한다. 그래서 **문장 단위로 비교하고 청크쌍으로 되모았다.**

### 🔴 축을 유사도 하나로 세우면 반드시 틀린다

| 문장 A | 문장 B | 원문 유사도 |
|---|---|---|
| 정규직의 기본 근무 시간은 주 **40**시간이며 1일 **8**시간 | 계약직의 기본 근무 시간은 주 **35**시간이며 1일 **7**시간 | **0.875** |
| 코어타임은 오전 **10**시부터 오후 4시까지다 | 코어타임은 오전 **11**시부터 오후 4시까지다 | **0.958** |

둘 다 중복이 아니라 **distractor** 다. 유사도만 보면 0.958 짜리를 중복으로 잡는다.
그래서 축을 둘로 나눴다.

- **`ratio_masked`**: 숫자를 `#` 로 가린 뒤의 유사도 = "**같은 항목을 말하는가**"
- **숫자 목록 일치 여부** = "**같은 값인가**"

| 조건 | 부류 |
|---|---|
| `ratio_masked ≥ 0.70` 이고 숫자 목록이 **같다** | **부류 1** (중복. 정답 청크로 쓰면 안 된다) |
| `ratio_masked ≥ 0.70` 이고 숫자 목록이 **다르다** | **부류 2** (distractor. 난이도의 원천이므로 살린다) |

**문턱 0.70 의 근거**: 0.70 아래로 내리면 "~하지 않는다" 류 보일러플레이트가 폭발한다
(0.60~0.70 구간에 64건이 더 있는데 대부분이 `연차 수당은 지급하지 않는다` ↔
`모니터 추가 지급은 하지 않는다` 같은 무관한 쌍이다). 0.80 으로 올리면 실제 쌍둥이를 놓친다.
즉 재현율과 정밀도의 타협점이고, **정밀도 쪽이 여전히 나쁘다**: 0.70 을 넘은 청크쌍 65개 중
사람이 읽어 살린 것은 20개뿐이다.

## 🔴 자동 판정을 하면 안 된다 (실측 증거)

요청서가 지목한 네 번째 사례 **"퇴직금 1년: `취업규칙#9` ≡ `31_퇴직_및_퇴직금#2`" 는
자동 문턱으로 안 잡힌다.**

```
ratio_masked = 0.698   문턱 0.70 을 0.002 차이로 못 넘는다
```

A: 퇴직금은 계속근로기간 1년에 대해 30일분 평균임금으로 산정한다. (`31_퇴직#2`)
B: 퇴직금은 근로자퇴직급여보장법에 따라 계속근로기간 1년에 대하여 30일분의 평균임금을 지급한다. (`취업규칙#9`)

**사람이 보면 같은 규정이고 기계는 0.002 차이로 놓친다.** 아래 §3-B 의 7쌍이 전부 이런 부류다.
문턱을 내려 잡으려 하면 무관한 쌍 수십 건이 함께 들어온다.
→ **이 문서의 목록은 도구가 낸 후보 65개를 한 쌍씩 읽어 가른 것이다. 문턱이 판정한 것이 아니다.**

## 7. 재현

스크립트는 저장소에 넣지 않았다 (§9 참고). 아래 코드를 그대로 파일로 만들어 돌리면
이 문서의 모든 숫자가 다시 나온다. **`ai-service` 디렉터리에서 실행한다.**

```bash
cd ai-service && .venv/bin/python <스크립트> <출력>.json
```

```python
"""코퍼스 중복 규정 전수 조사. 표준 라이브러리만 쓴다."""
from __future__ import annotations

import json, re, sys
from difflib import SequenceMatcher
from itertools import combinations
from pathlib import Path

sys.path.insert(0, str(Path.cwd()))          # ai-service 에서 실행한다
from app.parsers import extract_text
from app.chunker import chunk_text

CORPUS = Path("testdata/corpus")
_SENT_SPLIT = re.compile(r"(?<=[.。!?])\s+|\n+")
NUM = re.compile(r"[0-9]+(?:\.[0-9]+)?")


def sentences(content: str) -> list[str]:
    out = []
    for raw in _SENT_SPLIT.split(content):
        s = raw.strip()
        if s.startswith("#"):                # 제목 줄은 문장으로 세지 않는다
            continue
        s = s.lstrip("-*• ").strip()
        if len(s) >= 12:                     # 짧은 조각은 우연히 같을 수 있어 뺀다
            out.append(s)
    return out


def bigrams(s: str) -> set[str]:
    t = re.sub(r"\s+", "", s)
    return {t[i:i + 2] for i in range(len(t) - 1)}


ratio = lambda a, b: SequenceMatcher(None, a, b, autojunk=False).ratio()
mask = lambda s: NUM.sub("#", s)

chunks = []
for p in sorted(CORPUS.glob("*.md")):
    _, text = extract_text(p.name, p.read_bytes())
    for c in chunk_text(text, size=500, overlap=50, split_headings=True):
        chunks.append({"doc": p.name, "idx": c.index, "content": c.content})

sents = []
for i, c in enumerate(chunks):
    for s in sentences(c["content"]):
        sents.append((i, s, bigrams(s), bigrams(mask(s))))

cand = []
for (ai, a, abg, ambg), (bi, b, bbg, bmbg) in combinations(sents, 2):
    if ai == bi:
        continue
    # 값싼 선별: 바이그램 자카드. 이걸 안 하면 22만 쌍에 SequenceMatcher 를 다 돌린다
    j = len(abg & bbg) / len(abg | bbg) if abg & bbg else 0.0
    mj = len(ambg & bmbg) / len(ambg | bmbg) if ambg & bmbg else 0.0
    if j < 0.30 and mj < 0.30:
        continue
    cand.append({
        "a_chunk": ai, "b_chunk": bi, "a": a, "b": b,
        "ratio": round(ratio(a, b), 4),
        "ratio_masked": round(ratio(mask(a), mask(b)), 4),
        "nums_a": NUM.findall(a), "nums_b": NUM.findall(b),
    })

Path(sys.argv[1]).write_text(
    json.dumps({"chunks": chunks, "cand": cand}, ensure_ascii=False), encoding="utf-8")
print(f"청크 {len(chunks)} · 문장 {len(sents)} · 후보 문장쌍 {len(cand)}", file=sys.stderr)
```

출력 JSON 에서 부류를 가르는 것은 아래 두 줄이다.

```python
부류1 = [r for r in cand if r["ratio_masked"] >= 0.70 and sorted(r["nums_a"]) == sorted(r["nums_b"])]
부류2 = [r for r in cand if r["ratio_masked"] >= 0.70 and sorted(r["nums_a"]) != sorted(r["nums_b"])]
```

부류2 문장쌍 72(청크쌍 65).

## 9. 스크립트를 저장소에 넣지 않은 이유

일회성 조사 도구라 `ai-service/app/` 의 `*_check.py` 들과 성격이 다르다. 그것들은

두면 다음 사람이 "돌려서 초록불이면 중복이 없는 것" 으로 읽게 되고, 그것이 정확히
이 저장소가 반복해 낸 뭉개기다. 그래서 **코드를 문서 안에 §7 로 박아** 재현은 되게 하되
실행 파일은 늘리지 않았다.
