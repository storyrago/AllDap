## 1. 인증·인가 (사용자가 지정한 리팩토링 트랙)

이 셋은 **지금 없는 것이 버그가 아니라 선택**입니다. 왜 그런지를 함께 적습니다.
면접에서 물었을 때 "없습니다" 가 아니라 "알고 안 넣었습니다" 로 답할 수 있어야 합니다.

### 1-1. 리프레시 토큰

| | |
|---|---|
| 현재 | 액세스 토큰 하나. TTL **24시간** (`application.yaml:142`). 만료되면 다시 로그인 |
| 왜 안 했나 | 토큰을 짧게(15분) 두고 리프레시로 갱신하는 구조는 **저장소가 필요**하다. 리프레시 토큰은 회수할 수 있어야 의미가 있고, 회수하려면 서버가 상태를 가져야 한다. 그 자리가 지금 이 저장소에 없다 |
| 트리거 | **1-2 와 함께 한다.** 둘 다 같은 저장소(Redis 또는 `refresh_tokens` 테이블) 위에서 풀린다. 따로 하면 같은 인프라를 두 번 들인다 |
| 선행 | 저장소 선택. Redis 는 4-1(rate limit)과 같은 판단이라 **셋을 묶어서 결정할 것** |
| 볼 곳 | `api/.../auth/dto/AuthResponse.java:14` · `JwtService` · `JwtProperties` |
| 면접 각도 | "24시간은 보안과 편의의 절충인데, 토큰을 무효화할 수단이 없는 상태에서 TTL 을 길게 두는 건 그만큼 노출 창이 길다는 뜻입니다. 짧게 줄이려면 리프레시가 필요하고, 리프레시가 의미를 가지려면 회수 저장소가 필요합니다" |

### 1-2. 로그아웃 시 토큰 무효화

| | |
|---|---|
| 현재 | **불가능하다.** JWT 는 상태가 없어 서버가 "이 토큰 버려" 를 말할 수 없다. 프론트가 토큰을 지울 뿐이고, 이미 복사된 토큰은 TTL 이 끝날 때까지 유효하다 |
| 왜 안 했나 | 블랙리스트를 두면 **JWT 를 쓰는 이유(무상태)가 절반 사라진다.** 요청마다 저장소를 조회하게 되므로, 그럴 바엔 세션을 쓰는 게 정직하다. 이 트레이드오프를 알고 무상태 쪽을 골랐다 |
| 트리거 | 셋 중 하나가 생기면 필요해진다: **① 비밀번호 변경 기능** (바꿔도 옛 토큰이 살아 있으면 변경의 의미가 없다) · **② 탈퇴 기능** · **③ 실사용자 유입** |
| 설계 메모 | 전면 블랙리스트 대신 **`users` 에 `token_valid_after` 타임스탬프 한 칸**을 두고 그보다 이전에 발급된 토큰을 거부하는 방법이 있다. 조회가 어차피 있는 사용자 조회에 묻어가고, 개별 토큰이 아니라 "이 사용자의 모든 토큰"을 한 번에 끊는다. 비밀번호 변경·탈퇴 시나리오에는 이쪽이 더 맞는다 |
| 볼 곳 | `api/.../auth/filter/JwtAuthenticationFilter.java:59` (같은 취지의 TODO 가 이미 있다) |

## 3. 신뢰성 · 운영

### 3-1. 배포 롤백 경로가 없다

| | |
|---|---|
| 무엇 | 배포가 잘못되면 되돌릴 절차가 없다. **`IMAGE_TAG` 한 줄로는 되지 않는다** |
| 왜 | Flyway 마이그레이션이 이미 적용된 뒤라면 옛 이미지가 새 스키마를 만난다 |
| 트리거 | **다음번에 배포가 깨졌을 때 반드시 생각난다.** 그전에 하는 것이 낫다 |
| 볼 곳 | `docs/DEPLOY.md` §9 "롤백" |

### 3-2. `AiServiceClient.isHealthy()` 가 미구현이다

호출하면 `UnsupportedOperationException` 을 던진다. Spring 의 `/actuator/health` 에
커스텀 HealthIndicator 로 물려야 한다. **Python 이 죽으면 채팅이 죽는데 Spring 의 health 가
UP 이면 그게 거짓 신호다.** 이 저장소가 반복해 낸 "서로 다른 사실을 한 값으로 뭉개는" 부류다.
`AiServiceClient.java:663`

### 3-3. `AI_SERVICE_TIMEOUT`(504) 의 안내가 두 사실을 섞는다

"질문을 짧게 줄여서 다시 시도" 라고 안내하는데, 실제로는 **"느려서 못 받았다"** 와
**"질문이 커서 느리다"** 가 섞여 있다. 재시도가 통할 수도, 안 통할 수도 있다.
가르려면 Python 이 <어디서> 오래 걸렸는지를 말해줘야 하는데 그 신호가 없다.
`AGENTS.md` "남은 구멍" 절. 같은 부류의 앞 두 건(`ANSWER_INCOMPLETE` ·
`BILLING_METHOD_UNREADABLE`)은 2026-09-09 에 닫혔다.

### 3-4. Python `503` 이 하나 더 생기면 조용히 뭉개진다

지금 Python chat 의 503 은 "답변 잘림" 한 자리뿐이라 **우연히 신호 노릇을 한다.**
503 이 하나만 더 생기면 Spring 이 구분하지 못한다. 상태 코드가 아니라 `detail` 의
`code` 를 봐야 한다. **503 을 새로 추가하는 사람이 이 문단을 봐야 한다.**

### 3-5. 백그라운드 작업이 프로세스 종료 시 유실된다

FastAPI `BackgroundTasks` 라 업로드 처리 중에 프로세스가 죽으면 그 문서는 `processing` 에
영원히 남는다. Redis + RQ 로 교체해야 한다. **트리거는 실사용 트래픽이다.**

관련해서 **오래 `running` 인 평가 실행을 `failed` 로 정리하는 절차도 없다**
(`ai-service/app/main.py:786`).

### 3-6. rate limit 의 분 경계 flaky

`WidgetIntegrationTest > 한도는 봇마다 따로 센다` 가 분 경계에 걸리면 깨진다.
**CI 가 가끔 이유 없이 빨개지면 빨간불을 무시하는 습관이 생긴다.**
권고는 테스트를 경계에서 비키게 하는 것이고, 슬라이딩 윈도우 전환은 4-1 과 함께 하는 것이 자연스럽다.
`docs/HANDOFF-2026-09-13.md` §6 ④

### 3-7. `TOSS_SECRET_KEY` 에 기동 가드가 없다

`JWT_SECRET` · `BILLING_CRYPTO_KEY` 와 달리 비어 있어도 기동이 막히지 않는다.
`TossProperties` 가 순수 record 라 가드가 없어서, 빈 문자열이 주입돼도 컨테이너가 healthy 로 뜬다.
**증상은 카드를 등록할 때에야 401 → 503 으로 드러난다.**
`BillingCrypto` 처럼 시작 시 가드를 추가할 것. `application-prod.yaml:105` · `docs/DEPLOY.md` §7

### 3-8. CI 의 파이썬 버전이 운영과 다르다

| 환경 | Python |
|---|---|
| CI | **3.11** (`.github/workflows/ci.yml:176`) |
| 운영 | **3.13-slim** (`ai-service/Dockerfile:11`) |
| 로컬 venv | 3.13.9 (**못박힌 곳이 없다**) |

이번에는 CI 가 더 엄격해 좋은 쪽으로 걸렸지만, **반대 방향이면 CI 가 초록인데 운영이 깨진다.**
`ci.yml` 한 줄만 바꾸면 끝나지 않는다. `requirements.txt` 고정 버전이 3.13 에서 도는지 확인해야 하고,
`.python-version` 을 두어 로컬을 우연에 맡기지 않는 것이 함께 가야 한다.

> 🔴 **아래 셋은 "수평 확장을 시작하는 순간" 이라는 <같은 트리거>를 공유한다.**
> 따로 하지 말 것. 인프라(Redis)를 세 번 들이게 된다.

### 4-1. rate limit 이 인메모리다

인스턴스를 늘리면 각자 세므로 **실질 한도가 인스턴스 수만큼 배가 된다.**
`AGENTS.md` 가 "수평 확장 시작 시점이 교체(Redis) 시점" 이라고 못박아 뒀다.

### 4-2. 리프레시 토큰 · 토큰 무효화 (1-1, 1-2)

같은 저장소 위에서 풀린다.

### 4-3. 서킷브레이커가 인스턴스별이다

직접 만든 상태 3개짜리 카운터라 싱글턴이다. 인스턴스가 여럿이면 각자 판단한다.
지금 규모에서는 문제가 아니다.

> **오케스트레이터(Kubernetes)도 이 트리거에 걸린다.** 서버가 한 대인 동안에는
> 스케줄러가 정할 것이 없어서 도커 컴포즈로 충분하다. 위 셋이 필요해지는 시점이
> 오케스트레이터를 검토할 시점이기도 하다.
