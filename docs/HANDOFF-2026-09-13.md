## 1. Swagger PR 1 (#142) - 계획대로 갔고 지뢰는 안 터졌다

계획서(`docs/superpowers/plans/2026-09-12-swagger-pr1.md`)를 그대로 따랐다. Task 1~3 을 한 세션이
순차로, Task 4 의 컨트롤러 11개를 세 세션이 파일을 나눠 병렬로, 취합·브라우저 확인은 이 세션이 했다.

**계획서가 미리 대비해둔 미확인 지점 3개가 전부 안 터졌다.**

| 미확인 | 실제 |
|---|---|
| `DynamicPropertyRegistrar` 로 `DB_URL` 같은 환경변수 이름 플레이스홀더가 해석되는가 | 그대로 해석됐다. `properties` 에 아무것도 안 더했다 |
| prod 에서 `/swagger-ui/index.html` 이 404 인가 | 토큰을 붙여도 404. `denyAll` 을 추가할 필요가 없었다 |
| `Environment.matchesProfiles("prod")` 가 Boot 4 에서 쓰이는가 | 그대로 컴파일·동작. 대안(`acceptsProfiles`)을 안 썼다 |

**브라우저 확인에서 설계가 의도대로 동작하는 것을 봤다.** `/v3/api-docs` JSON 을 직접 파싱해
대조하니 **401 이 없는 4개와 `security: []` 인 4개가 정확히 일치**했다.
`@SecurityRequirements` 하나를 신호로 쓴 것이 실제로 자동으로 맞아떨어진다는 증거다.

⚠️ **기존 테스트의 flaky 하나를 봤다.** `WidgetIntegrationTest > 한도는 봇마다 따로 센다` 가
`expected 429 but was 503` 으로 한 번 깨졌다. 단독 실행은 통과하고 재실행하면 초록이다.
원인은 `RateLimiter.key()` 의 `System.currentTimeMillis() / window.toMillis()` 다.
**절대 분 경계를 쓰는 고정 윈도우**라, 앞 3회와 4번째 사이에 분이 바뀌면 카운터가 리셋돼
429 로 안 막히고 가짜 AI 로 넘어가 503 이 된다. `RateLimiter` 주석이 이미 인정해둔 한계다.
**이 PR 범위 밖이라 손대지 않았다.** 6절 ④ 참고.

## 2. 🔴 PR 2 를 조사까지 하고 접었다. 그 조사가 값을 했다

PR 2 는 인증·봇·문서 10개에 엔드포인트별 `@ApiResponse` 를 다는 것이었다.
**애노테이션을 쓰기 전에 조사를 먼저 시켰다.** 각 엔드포인트가 <실제로> 낼 수 있는 응답이
무엇인지 확인해야 했기 때문이다. `ErrorCode` 는 36개인데 어느 엔드포인트가 그중 몇 개를
실제로 내는지는 코드를 따라가야만 안다. **없는 응답을 문서에 적으면 문서가 거짓말을 한다.**

그 조사가 세 가지를 찾아냈다.

1. 🔴 **`LEGACY_HWP_NOT_SUPPORTED` 가 죽은 코드다.** 정의만 있고 사용처 0건이었다.
   실제로 `.hwp` 를 올리면 Python 의 400 이 `UNSUPPORTED_FILE_TYPE` 으로 변환되고
   Python 의 한국어 문구가 실려 나간다. **이름만 보고 적었으면 없는 응답을 적을 뻔했다.** 그래서 #143.
2. **업로드와 삭제의 4xx 해석이 다르다.** 업로드는 `translateUploadClientError` 를 넘겨
   413 을 `FILE_TOO_LARGE`, 400 을 `UNSUPPORTED_FILE_TYPE` 로 가르지만, **삭제는 매퍼를 안 넘겨
   4xx 가 전부 502** 다. 같은 컨트롤러인데 표를 복사하면 틀린다.
3. **문서 목록 조회는 Python 을 아예 안 부른다.** DB 직접 조회라 502·503·504 가 날 수 없다.

**그리고 조사를 마친 뒤 PR 2 자체를 접었다.** 기각 사유는 "문서가 쓸모없다" 가 아니라
**<읽을 사람이 없다>** 다. 이 API 를 쓰는 곳은 `web/` 하나뿐이고 **이미 완성돼 있다.**
프론트를 짜면서 코드를 직접 읽어 이미 알아냈다. 근거는 `docs/decisions.md` 2026-09-13 항목.

조사 3편은 `docs/superpowers/surveys/` 에 남겼다 (auth 179줄 · bot 211줄 · document 175줄).
각 파일 머리말에 **조사 시점 커밋(`59f86e9`)** 을 적어뒀다. 코드가 바뀌면 파일·줄 근거가 낡는다.

📌 **bot 조사의 6절은 PR 2 와 무관하게 값어치가 남는다.** "남의 봇은 403 이 아니라 404" 와
"`allowedOrigins` 가 비면 전부 차단" 이 어디서 강제되고 어디에 근거가 적혀 있는지를 한자리에 모았다.
둘 다 반대로 읽히면 곧바로 보안 오해가 되는 규칙이다.

## 4. 🔴 이 라운드의 핵심: 같은 부류의 실패를 세 번 겪었다

AGENTS.md 의 "낸 버그" 표가 여덟 건을 "원인이 다른 사실을 같은 값으로 뭉갰다" 로 묶어뒀다.
**이번 셋은 그 친척이되, 어긋난 자리가 <검사> 쪽이다.**

### ① 검사가 원리적으로 실패할 수 없었다

`openapi_check.py` 의 첫 판이 설명 유무를 `summary or description` 으로 봤다.
**그 상태에서 `chat` 의 docstring 을 통째로 지워도 16/16 통과했다.**

```
fastapi/openapi/utils.py  generate_operation_summary()
    if route.summary: return route.summary
    return route.name.replace("_", " ").title()   ← 함수 이름에서 만든다
```

**`summary` 는 항상 채워진다.** `or` 의 앞쪽이 늘 참이라 뒤쪽은 평가되지도 않았다.
오픈 리다이렉트와 배포 rate limit 점검은 "짜둔 검사가 아무 데서도 안 돌았다" 였는데,
**이번 것은 돌면서 초록불을 준다.** 한 걸음 더 나간 것이다.

→ 둘을 <따로> 요구하게 고쳤고, 파일 상단에 FastAPI 소스를 인용해 근거를 남겼다.

### ② 고친 뒤 주입 실험으로 확인했다. 그런데 <확인한 환경>이 틀렸다

①을 고치고 일곱 번 주입해 "걸린다" 를 확인했다. 그 뒤 화면이 난잡하다는 지적을 받아
docstring 렌더링을 `\f` 로 껐고, 그것도 주입 실험으로 확인했다. **그리고 CI 가 16건 전부 실패했다.**

| Python | `inspect.cleandoc` 후 맨 앞 `\f` | 결과 |
|---|---|---|
| **3.13** (로컬 venv · **운영**) | 살아남음 | FastAPI 가 잘라냄. `description` 없음 |
| **3.11** (**CI 만**) | **지워짐** | 자를 지점이 없음. 설명이 그대로 새어나감 |

🔴 **처음에는 "운영도 3.11" 이라고 판단했는데 <틀렸다>.** `ai-service/Dockerfile:11` 이
`FROM python:3.13-slim` 이다. **어긋난 것은 운영이 아니라 CI 다.** 즉 `\f` 방식이었어도
운영에서는 실제로 동작했을 것이고, CI 만 3.11 이라 거기서 걸렸다.

**그래도 고친 것이 옳다.** ① CI 가 빨간 채로는 머지할 수 없다.
② 새 방식(`description=" "`)은 두 버전 모두에서 동작한다. 버전에 딸려 있지 않은 쪽이 낫다.
③ 🔴 그리고 이 조사가 <진짜 문제>를 드러냈다. 아래 ③ 참고.

3.11 은 첫 줄에 `lstrip()`(모든 공백 제거)을 걸고 **`\f`(form feed)도 파이썬이 공백으로 친다.**
3.13 은 `lstrip(' ')`(스페이스만)으로 바뀌어 살아남는다. 두 버전을 실제로 띄워 확인했다.

🔴 **교훈: 검사를 로컬에서만 확인하면 <그 검사가 무엇을 보는지>까지만 알 뿐,
운영에서 같은 결과가 나오는지는 모른다.** 검사도 돌았고 나도 확인했는데, **확인한 곳이 틀렸다.**

→ `\f` 를 빼고 데코레이터에 `description=_NO_DESCRIPTION`(**공백 한 칸**)을 준다.
빈 문자열은 거짓값이라 `description or cleandoc(docstring)` 에서 docstring 으로 떨어진다
(이것도 실측했다). 두 버전 모두 `description=None` 이 되는 것을 확인했다.

### ③ 🔴 더 근본적인 것: CI 가 <운영에 안 나가는 파이썬>으로 검사하고 있다

| 환경 | Python | 어디에 적혀 있나 |
|---|---|---|
| 로컬 venv | 3.13.9 | **아무 데도 없다.** `.python-version` 이 없다 |
| CI | **3.11** | `.github/workflows/ci.yml:176` |
| 운영 | **3.13-slim** | `ai-service/Dockerfile:11` |

**CI 가 혼자 다르다.** 이번에는 CI 가 더 엄격해서 우연히 좋은 방향으로 걸렸지만,
**반대 방향이면 CI 가 초록인데 운영이 깨진다.** 그게 CI 의 존재 이유와 정면으로 어긋난다.

그리고 **`.python-version` 이 없어서 로컬 버전은 우연에 맡겨져 있다.** 개발자가 파이썬을
새로 깔면 또 달라진다. 6절 ③ 참고.

> **이 셋을 한 줄로 묶으면**: 지금까지는 "검사를 짰는가" 와 "그 검사가 도는가" 를 물었다.
> 이번에 질문이 하나 더 붙는다. **"그 검사를 <운영과 같은 환경>에서 확인했는가."**

### ④ rate limit 의 분 경계 flaky (새로 생긴 항목)

1절 참고. `WidgetIntegrationTest > 한도는 봇마다 따로 센다` 가 분 경계에 걸리면 깨진다.
**CI 가 가끔 이유 없이 빨개지면 빨간불을 무시하는 습관이 생긴다.** 그게 이 저장소가
제일 경계하는 경로다. 두 갈래가 있다.

| 방법 | 대가 |
|---|---|
| 테스트를 경계에서 비키게 한다 | 싸다. 다만 운영 코드의 한계는 그대로 남는다 |
| 슬라이딩 윈도우로 바꾼다 | 리미터가 몇 배 복잡해진다. 실제 우회 가능성도 같이 닫힌다 |

권고는 첫째다. `RateLimiter` 주석이 "우리 목적은 정밀한 유량 제어가 아니라 무한 호출 차단" 이라
판단해뒀고 그 판단은 여전히 맞다. 슬라이딩은 수평 확장으로 Redis 를 들일 때 함께 하는 것이 자연스럽다.
