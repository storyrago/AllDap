## 1. 🔴 `themeColor` 슬라이스의 전제가 바뀌었다 (#126)

앞 핸드오프는 색상 커스텀을 **"`V9` 한 장 + `from()` 한 줄 + 입력 한 칸"** 이라고 적었다. **그게 아니다.**

```js
// widget/alldap-widget.js:552
/* ⚠️ 이 분기는 지금 <한 번도 실행되지 않는다.> 서버는 색 필드를 themeColor 라는 ... */
if (data.primaryColor) {
```

로더는 `data.primaryColor` 를 읽는데 Spring(`WidgetConfigResponse.java:29`)과 프론트(`web/lib/types.ts:435`)가 쓰는 이름은 `themeColor` 다. 서버가 지금 그 자리에 `null` 을 박아 넣어서 드러나지 않을 뿐, **컬럼만 추가하고 이름을 안 맞추면 색이 조용히 무시된다.** 마이그레이션도 돌고 DTO 도 채워지고 화면에서 색도 고를 수 있는데 위젯만 파란색으로 남는다.

🔴 **게다가 컬럼 이름 후보부터 두 갈래다.**

| 어디 | 가리키는 이름 |
|---|---|
| `api/` 의 `WidgetConfigResponse` TODO · `web/lib/types.ts` | `theme_color` |
| `widget/` 옛 주석 · `widget/demo.html` · `widget/README.md` | `bots.primary_color` |

**즉 이 슬라이스의 첫 일은 마이그레이션이 아니라 <이름을 하나로 정하는 것>이고, 그건 컨트랙트 변경이다.** 정하고 나면 세 곳(SQL 컬럼 · Spring DTO 필드 · 로더가 읽는 키)이 같은 말을 해야 한다.

#126 이 코드를 안 고친 것은 옳다. 이름을 맞추는 것은 동작 변경인데 **지금은 검증할 대상(컬럼)이 없다.** 대신 사실을 세 자리에 적어뒀다.

## 3. 🔴 "84건" 이 부정확했다 (#128 이 넓혔지만 한계는 같다)

PR #121 이 파서 경계 검사의 근거로 든 "**84건 중 달라진 것 0건**" 을 앞 핸드오프가 "두 드라이버가 내는 조회 전부" 라고 옮겼다. **범위가 부정확하다.**

```
84  = S4 조회 14종 × 캡처 3건 × 순서 2가지
114 = S3·S4 조회 19종 × 캡처 3건 × 순서 2가지   (#128 이 넓힌 것)
```

**대조에 쓴 캡처가 `results/S4-*-prom-after.txt` 3건뿐이다.** `results/` 에 **S3 의 prometheus 노출 원문은 파일로 없다**(S3 는 `*-context.json` 에 값만 남겼다). 즉 **S3 노출 원문으로 파서를 대조한 사람은 여전히 없다.**

🔴 **#128 이 조회 5종을 더해 114건으로 넓혔지만 그 5종은 S4 캡처에 시계열이 없어 양쪽 파서가 다 `None` 을 돌려준다.** "0건 달라졌다" 는 참이지만, 그 5종에 대해서는 **아무것도 안 물어본 것과 구별되지 않는다.**

> **"몇 건을 대조했다" 와 "무엇에 대고 대조했다" 는 다른 사실이다.**
> 큰 숫자는 범위를 넓혀 보이게 하는데, 늘어난 것이 <같은 캡처에 대한 질문 수>뿐일 수 있다.

**#128 자체는 잘 닫혔다.** `float("NaN")` 이 예외를 안 내고 `nan` 으로 통과해 "계측이 살아 있다" 와 "계측이 죽어 NaN 이다" 를 뭉개던 것을 갈랐고, **`+Inf`·`-Inf` 도 같은 구멍이라 함께 막았다**(앞 핸드오프는 NaN 만 적었다). 걱정했던 측정 재실행은 **불필요했다**: 값 대조 114건에서 달라진 것이 0건이고 캡처에 `NaN`·`Inf` 토큰 자체가 0건이었다.

### ⓓ `git merge-base --is-ancestor` 는 스쿼시 머지를 못 잡는다

alldap-6d 가 `docs/rollback-procedure` 를 **"미머지"** 로 보고했다가 스스로 뒤집었다.
확인해보니 그대로다.

```
PR #104 의 머지 커밋 74b9ef2 의 부모: 29a9959  (하나뿐 = 스쿼시)
git merge-base --is-ancestor 78085eb origin/main  ->  NO

```

스쿼시 머지는 브랜치 커밋들을 **새 SHA 하나로 다시 쓴다.** 그래서 원본 tip 은
`main` 의 조상이 아니게 되고, `--is-ancestor` 는 **"안 들어갔다"** 고 답한다.

🔴 **이 저장소의 상습 부류다: "조상이 아니다" 와 "내용이 안 들어갔다" 를 같은 값으로 뭉갠 것.**
낸 버그 표의 일곱 건과 같은 모양이고, 이번에는 **지표도 응답 코드도 아닌 git 명령**에서 나왔다.
머지 여부는 SHA 계보가 아니라 **PR 상태(`gh pr view`)나 내용 대조**로 확인할 것.
