## 3. 실측으로 고정된 사실 (2026-09-20)

```
eval_results (run 11~16)   156행 = 26문항 × 6회
  처리 실패                  0건
  중복 제거                 46건  (문항 · 답변문자열 · 근거집합)
  fallback 제외             44건  ← 모집단. 표본이 아니다
채점자 충실성 분포          1.0 ×40 · 0.5 ×3 · 0.0 ×1
근거 청크                  run 11~13 은 95개 · 14~16 은 100개. 전부 chunks 에 살아 있다
근거 전문 최대 길이         217자  (preview 200자가 아니라 전문이라는 증거)
```

⚠️ **217자가 뜻하는 것 하나**: 이 코퍼스는 `chunk_split_headings=True` 라 청크가
최대 217자다. 즉 **지금 코퍼스에서는 preview(200자)와 전문의 차이가 17자뿐**이고,
2026-08-02 의 "채점자가 앞 200자만 봐서 250번째 글자의 HR-310 을 못 봤다" 는 버그는
지금 코퍼스에서 재현되지 않는다. 그래도 전문을 싣는 것은 맞다(코퍼스가 바뀌면 되살아난다).

### 3-1. 🔴 카파는 0.000 이 나올 것이다. 버그가 아니다

지금 분포에서 **사람이 44건을 전부 1.0 으로 본다면** 이렇게 된다(계산해 확인했다):

```
일치율 90.9%   ·   선형가중 카파 0.0000   ·   방향 (후함 0, 박함 4, 일치 40)
```

한쪽 평정자가 한 값에 고정되면 우연 일치 기대치가 관측 일치와 같아져 **분자가 정확히 0**
이 된다. **채점자가 44건 중 40건을 맞혔는데도 카파는 "우연 수준" 으로 읽힌다.**
그리고 이 시나리오는 꽤 있을 법하다 (채점자가 박하게만 틀렸다면 사람 라벨은 전부 1.0 이 된다).

`check_kappa_paradox_is_real_on_this_distribution` 이 이것을 못박아 두었다.
**목적은 미래의 누군가가 출력의 주석을 지우고 카파만 인용하는 것을 막는 것이다.**

### 3-2. 🔴 가짜 라벨로 본 예고편 (주장이 아니다)

라벨을 전부 1.0 으로 채운 극단 가정에서 `[3]` 왜곡량이 이렇게 나왔다.

| run | 청크 | 채점자 기준 | 사람 기준(가정) | 차이 |
|---|---|---|---|---|
| 11 · 12 · 13 | 306 | 0.9231 | 0.9231 | **+0.0000** |
| 14 | 360 | 0.8462 | 0.9231 | **+0.0769** |
| 15 | 360 | 0.8654 | 0.9231 | +0.0577 |
| 16 | 360 | 0.8846 | 0.9231 | +0.0385 |

**306청크 셋은 차이가 정확히 0 이고 360청크 셋만 벌어진다.** 벌어지는 폭이 실측 편차
0.032 를 전부 넘는다. 이것이 2026-09-18 에 *"코퍼스가 난이도가 아니라 <채점>을 때렸다"*
고 쓴 그 구간이다.

🔴 **이 표를 결과로 인용하지 말 것.** "사람이 전부 1.0 을 준다면" 이라는 가정 위의
숫자이고, 진짜 라벨이 붙으면 확정되거나 반증된다. **예고편이지 결과가 아니다.**

## 4. 🔴 이 슬라이스에서 잡은 것 셋 (구현 중에 나왔다)

전부 구현 세션이 보고했고 주 세션이 고쳤다. **셋 다 "검사가 검사하지 않는" 부류다.**

**① 블라인드 검사가 낱말을 찾고 있었다** (`a1b1267`).
`assert "judge" not in blob` 이 <우연히> 통과하는 상태였다. 두 방향으로 거짓이 된다:
근거 본문에 그 글자가 섞이면 블라인드가 멀쩡한데도 실패하고(이 저장소의 "정상을 실패로
부르는 검사" 부류), 점수가 다른 이름의 칸으로 새면 그냥 지나간다.
→ **허용된 칸 목록**을 고정하는 방식으로 바꿨다. 그리고 `build_payload` 에
`judge_faithfulness` 를 일부러 새어나가게 해 **실제로 걸리는지 눈으로 봤다**
(종료코드 1 + `허용되지 않은 칸이 생겼습니다: ['judge_faithfulness']`).

**② 카파 역설이 주석으로만 있었다** (`9c1b459`). 출력에 경고 문구는 있는데 검사가 없었다.
→ §3-1 을 실행 가능한 검사로 못박았다.

**③ 🔴 열 번째 뭉개기가 될 뻔했다** (`a4257e6`). **이것이 가장 중요하다.**
채점 재호출이 실패하면 `NaN` 을 돌려주고 있었는데 **`float("nan") != x` 는 언제나 참**이라
"점수가 달라졌다" 분기를 그냥 지나간다. 호출이 한 번 실패했을 뿐인데 화면에는
*"🔴 재호출 점수가 DB 값과 다릅니다 ... 채점자가 결정적이라는 전제가 성립하지 않습니다"*
가 찍힌다. **거짓이고, 하필 이 슬라이스가 주장하려는 바로 그 문장이다.**
→ 실패를 `None` 으로 바꾸고, 판정을 `rescore_verdict(again, stored)` 순수 함수로 뽑아
`unmeasured` / `same` / `differs` 셋으로 갈랐다. 검사가 **NaN 을 넣으면 셋이 전부
`differs` 로 뭉개진다는 것까지** 보여준다.

> 📌 **앞의 아홉은 <사후에> 발견한 것이고 ③ 은 <나가기 전에> 잡은 것이다.**
> AGENTS.md 가 여덟 번째 뒤에 세워둔 질문이 그대로 먹혔다:
> *"이 값을 읽지 못했을 때와 읽어서 이 값이 나왔을 때가 구분되는가."*
> 면접 재료로 쓸 때 이 차이를 분명히 할 것. 규칙을 만든 것과 그 규칙이 실제로 작동한 것은 다른 사실이다.

## 6. ⬜ Task 7: 사람이 44건을 라벨링한다 (개발자의 일)

🔴 **에이전트가 라벨을 채우면 이 슬라이스가 통째로 무의미해진다.** 재는 대상이
LLM 채점자인데 기준자도 LLM 이면 아무것도 못 잰다.

```
cd ai-service && .venv/bin/python -m app.judge_agreement dump
# testdata/judge_labels.json 을 에디터로 열어 label 칸을 채운다
.venv/bin/python -m app.judge_agreement report --reasons
```

**기준 (파일 `_readme` 와 같고, `judge.py` 의 `SYSTEM_PROMPT` 와 같아야 한다)**:
충실성 = **답변의 모든 주장이 그 아래 근거에 실제로 적혀 있는가.**

| 값 | 뜻 |
|---|---|
| `1.0` | 답변의 모든 주장이 근거에 있다 |
| `0.5` | 일부는 근거에 있고 일부는 없다 |
| `0.0` | 근거에 없는 내용을 지어냈다 |

⚠️ **답이 세상의 상식에 맞는지는 보지 않는다. 사실이더라도 근거에 없으면 깎는다.**
기준이 채점자와 다르면 불일치가 "채점자가 틀렸다" 가 아니라 **"둘이 다른 것을 쟀다"** 가 된다.

- 중간에 끊어도 된다. 다시 `dump` 를 돌려도 채운 칸은 `case_id` 로 보존된다.
- 덜 채우고 `report` 를 돌리면 **실패한다**(부분 집계를 내지 않는다). 의도한 동작이다.
- 예상 소요 1.5~2시간.

### 결과를 남길 곳 (하나라도 빠뜨리지 말 것)

1. **`AGENTS.md`**: "난이도 확보 시도" 절 아래에 새 절. 담을 것:
   혼동행렬 · **후함 N건 / 박함 N건과 그 방향** · run 별 왜곡량과 **편차 0.032 와의 비교** ·
   `--reasons` 가 준 사유 중 **사실과 다른 것이 있는지** ·
   ⚠️ 한계(44건은 **한 봇 · 한 코퍼스 · 한 채점 모델**이다) ·
