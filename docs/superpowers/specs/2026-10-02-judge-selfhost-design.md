# 설계: 공개 채점 모델을 코랩에서 돌려 사람 라벨과 대조하기 (2026-10-02)

이 문서는 지금 Cloudflare 에서 쓰는 채점 모델과 직접 돌리는 공개 모델 셋을, 사람이 매긴 충실성 라벨 44건과 대조하는 실험의 설계다.
이 실험은 모델을 학습시키지 않는다. 이미 공개된 모델을 그대로 돌려 채점만 시킨다.
배경 조사는 [`docs/자체모델-전환-조사-2026-10-02.md`](../../자체모델-전환-조사-2026-10-02.md) 에 있다.

| 후함, 박함 | 모델 점수가 새 라벨보다 높으면 후함, 낮으면 박함 |
| 뉴런 | Cloudflare Workers AI 의 사용량 단위. 무료 한도는 하루 10,000 이다 |
| M1 ~ M4 | 비교하는 네 모델. 2절 표 참고 |

## 1. 왜 이 실험을 하는가

### 1-1. 동기

사용자는 Cloudflare 가 대신 돌려 주는 모델들을 직접 고른 모델로 바꾸는 방향을 검토하고 있다(2026-10-02). 그 첫 대상으로 채점 모델을 고른 이유는 셋이다.

1. 비용이 가장 큰 자리다. 평가 1회(16문항)에 드는 804 뉴런 중 채점이 410 뉴런으로 약 51% 다(`docs/실측-기록.md` 의 회당 비용 절).
2. 바꾼 뒤의 품질을 잴 자가 이미 있다. 사람이 매긴 라벨 44건이다.
3. 채점 모델은 14B 급 공개 모델로도 후보가 있다. 코랩 무료 GPU(T4, 메모리 16GB)에 4비트로 올라간다.

### 1-2. 입력 데이터

사례 44건은 옛 라벨 파일 `ai-service/testdata/judge_labels.json` 에 이미 들어 있다. 평가 실행 11~16번(봇 1번, 2026-09-18 전후)의 채점 결과에서 같은 답변의 중복과 fallback 을 뺀 전부다. 각 사례에는 질문, 기대 답변, 생성된 답변, 근거 청크 전문이 있다. 따라서 이 실험은 DB 없이 이 파일에서 시작할 수 있다.

옛 라벨의 분포는 1.0 이 40건, 0.5 가 2건, 0.0 이 2건이다. 지금 채점 모델은 옛 라벨과 40건이 일치했다(일치율 90.9%, 2026-09-25).

### 1-3. 왜 다섯 칸으로 바꾸는가

옛 라벨은 세 칸이라 "근거에 없는 사소한 주장이 하나 있다" 와 "주장의 절반을 지어냈다" 가 모두 0.5 가 된다. 두 경우는 위험의 크기가 다르다. 따라서 이 실험은 다섯 칸을 쓴다. 다섯 칸을 1~5 로 정한 이유는 M3 가 1~5 로 학습된 채점 모델이라서다. 0 을 더한 여섯 칸은 M3 가 배운 적 없는 칸을 만든다.

서비스의 채점 방식(0~1 실수)은 이 실험에서 바꾸지 않는다. 서비스 쪽을 바꾸면 지금까지 쌓인 평가 기록과 새 점수를 이어 붙일 수 없다. 이 실험에서 다섯 칸이 사람과 더 잘 맞는다는 결과가 나오면 그 결과가 서비스 쪽을 바꿀 근거가 된다. 그 결정은 이 실험 뒤에 따로 한다.

## 2. 비교하는 네 모델

| 이름 | 모델 | 어디서 돌리나 | 이 모델을 넣은 이유 |
|---|---|---|---|
| M1 | `@cf/mistralai/mistral-small-3.1-24b-instruct` | Cloudflare API | 지금 서비스의 채점 모델. 기준선이다 |
| M2 | `mistralai/Mistral-Small-3.1-24B-Instruct-2503`, 4비트 | 코랩 | M1 과 같은 모델이다. 돌리는 곳과 4비트 양자화만 다르다 |
| M3 | `Unbabel/M-Prometheus-14B`, 4비트 | 코랩 | 채점 전용으로 학습된 다국어 모델이다 |
| M4 | `Qwen/Qwen2.5-14B-Instruct`, 4비트 | 코랩 | M3 의 바탕 모델이다. 모델 카드가 M3 를 이 모델에서 파인튜닝했다고 밝힌다(2026-10-02 확인) |

코랩의 세 모델은 모두 같은 방식(bitsandbytes 4비트 NF4)으로 올린다. M4 를 원래 정밀도로 올리면 약 28GB 라 T4 에 들어가지 않는다. 따라서 셋의 조건을 맞추려고 모두 4비트로 올린다.

이 구성으로 답할 수 있는 질문은 셋이다(4-3절).

1. M1 과 M2 를 비교하면, 돌리는 곳과 4비트 양자화가 점수를 바꾸는지 알 수 있다.
2. M4 와 M3 를 비교하면, 같은 바탕 모델에 채점 학습을 더한 효과를 알 수 있다.
3. 가장 나은 후보와 M1 을 비교하면, 서비스의 채점 모델을 바꿔도 되는지 알 수 있다.

답변 생성 모델은 Meta 의 llama 계열이다. 네 모델은 모두 llama 계열이 아니다. 따라서 "답변을 만든 모델이 자기 답변을 채점하면 안 된다" 는 규칙(`judge.py` 첫 주석)에 걸리지 않는다.

## 3. 무엇을 어떻게 채점시키는가

### 3-1. 채점표

사람과 네 모델이 모두 이 표를 쓴다.

| 점수 | 뜻 |
|---|---|
| 5 | 답변의 모든 주장이 근거에 적혀 있다 |
| 4 | 답변의 핵심 답은 근거와 일치한다. 다만 근거에 없는 사소한 주장이 하나 있다 |
| 3 | 근거에 있는 주장과 근거에 없는 주장이 비슷한 정도로 섞여 있다 |
| 2 | 답변의 주장 대부분이 근거에 없다 |
| 1 | 답변이 근거와 관계없는 내용을 지어냈거나, 근거와 반대되는 내용을 말한다 |

판단 원칙은 옛 라벨과 같다. 답변이 세상의 상식에 맞는지는 보지 않는다. 사실이더라도 근거에 없으면 깎는다.

### 3-2. 공통 지시문

네 모델에게 M3 가 학습한 양식(Prometheus 의 절대 평가 양식)을 똑같이 준다. 양식은 영어 지시문 틀이고, 그 안의 근거, 질문, 답변, 채점표는 한국어 그대로 넣는다. 출력은 `Feedback: (이유) [RESULT] (1~5 정수)` 다.

시스템 프롬프트와 지시문 틀은 M-Prometheus 모델 카드가 따르라고 한 Prometheus-2 모델 카드의 원문과 글자까지 같게 둔다. 처음 구현에는 시스템 프롬프트에 원문에 없는 "a" 가 한 글자 들어가 있었다("based on a specific criteria"). 2026-10-02 에 사용자가 원문("based on specific criteria")에 맞추기로 결정했고, 모델 출력을 하나도 보기 전에 고쳤다.

이렇게 정한 이유는 둘이다.

1. M3 에게 낯선 양식을 주면 M3 의 점수가 실력보다 낮게 나올 수 있다.
2. M3 에게만 다른 양식을 주면 네 모델의 입력이 달라진다. 모두에게 같은 양식을 주면 입력 차이가 사라진다.

공통 지시문에는 기대 답변(정답 예시)을 넣지 않는다. 충실성은 근거만 보고 판단하는 지표다. 사람도 새 라벨을 매길 때 근거만 본다. 지금 서비스의 채점 지시문은 관련성 채점 때문에 기대 답변을 함께 넣는다. 따라서 이 실험의 M1 점수는 서비스에서 나오는 M1 점수와 같은 값이 아니다.

공통 지시문의 본문은 구현에서 파일 하나(공통 채점 모듈)에 고정한다. Cloudflare 채점 도구와 코랩 노트북이 같은 본문을 쓰는지는 시험지 파일에 지시문 본문의 해시를 함께 적어 확인한다.

### 3-3. 생성 설정

- 네 모델 모두 탐욕적 디코딩으로 생성한다(Cloudflare 는 `temperature = 0`). 채점 모델이 같은 입력에 다른 점수를 주면 기준으로 쓸 수 없기 때문이다.
- 최대 출력은 512 토큰이다. 이유를 쓰고 끝에 점수를 쓰는 양식이라 짧게 자르면 점수가 잘린다.
- 코랩의 세 모델은 각각 시험지 전체를 **두 번** 채점한다. 두 번의 점수가 다른 사례 수를 기록한다. 비교에는 첫 번째 실행을 쓴다.
- 모델이 쓴 이유(Feedback)도 저장한다. 점수는 맞았는데 이유가 근거와 다른 경우를 사후에 볼 수 있게 하기 위해서다. 서비스는 지금 이 이유를 버린다(`docs/BACKLOG.md` §6).

## 4. 판정 규칙 (측정 전에 고정한다)

이 절은 모델 출력을 하나도 보기 전에 커밋한다. 결과를 본 뒤 규칙을 바꾸면 유리한 쪽으로 맞추게 되기 때문이다.

### 4-1. 순서

1. 사람이 새 라벨 44건을 먼저 매긴다. 이때 옛 라벨과 어떤 모델의 점수도 보지 않는다.
2. 새 라벨을 커밋한 **뒤에** 네 모델을 돌린다.

### 4-2. 모델마다 내는 수치

- 새 라벨과 정확히 같은 사례 수, 거리 1 이하인 사례 수, 평균 거리
- 후함 사례 수와 박함 사례 수 (합치지 않는다. 후한 채점 모델은 품질을 실제보다 좋게 보이게 하고, 박한 채점 모델은 그 반대라서 위험의 종류가 다르다)
- 못 읽음 사례 수
- 혼동행렬. 행 5개는 새 라벨, 열 5개는 모델 점수다
- 선형 가중 카파. 보조로만 쓴다. 옛 라벨처럼 한 칸에 사례가 몰리면 카파가 일치율과 동떨어지게 낮게 나오기 때문이다(`tools/judge_agreement.py` 머리 주석)

### 4-3. 두 모델 비교의 판정

비교는 2절의 셋이다: M1 과 M2, M4 와 M3, 그리고 가장 나은 후보와 M1. 가장 나은 후보는 M2, M3, M4 중 거리 1 이하 사례 수가 가장 많은 모델이다. 같으면 평균 거리가 작은 모델, 그래도 같으면 못 읽음이 적은 모델, 그래도 같으면 이름 순서(M2, M3, M4)로 앞선 모델이다.

1. 두 모델 중 하나라도 못 읽음인 사례는 그 비교에서 빼고, 뺀 수를 함께 적는다.
2. 남은 사례마다 거리가 더 작은 모델을 센다. 거리가 같은 사례는 뺀다.
3. 센 결과로 양측 부호 검정을 한다. p < 0.05 이면 "더 가까운 모델이 사람에 더 가깝다" 고 적는다. 아니면 "구별되지 않음" 이라고 적는다.

### 4-4. 교체 후보의 기준

"구별되지 않음" 은 "같다" 의 증거가 아니다. 따라서 바꿔도 되는지는 따로 정한다. 아래 셋을 모두 만족하는 모델을 교체 후보라고 부른다.

1. 거리 1 이하 사례 수가 M1 보다 적지 않다.
2. 못 읽음 사례가 0건이다.
3. M1 과의 부호 검정에서 M1 이 사람에 더 가깝다는 결과가 나오지 않는다.

교체 후보가 나와도 이 실험에서 서비스의 채점 모델을 바꾸지 않는다. 운영 서버(EC2)는 메모리가 1GB 라 이 모델들을 돌릴 수 없다. 교체를 어떻게 할지는 별도 결정이다.

### 4-5. 결과를 미리 해석해 둔다

44건은 적다. 옛 라벨 기준으로 M1 은 이미 40건이 일치했다. 따라서 대부분의 비교가 "구별되지 않음" 으로 나올 가능성이 크다. 그 경우의 해석을 미리 적어 둔다.

- 모든 비교가 구별되지 않음이면: 44건으로는 채점 모델 사이의 차이를 가를 수 없다. 다음 단계(7절)로 가기 전에 사람 라벨 사례 수를 늘려야 한다.
- M3 가 M4 보다 사람에 더 가까우면: 같은 바탕 모델에서 채점 학습이 효과가 있었다. 우리가 직접 채점 학습을 할 근거가 된다.
- M2 가 M1 과 구별되면: 돌리는 곳이나 4비트 양자화가 채점을 바꾼다. 이 경우 M3, M4 의 결과도 4비트의 영향을 받았을 수 있다고 함께 적는다.

### 4-6. 보조 확인: 사람 라벨의 일관성

새 라벨을 옛 라벨의 세 칸으로 옮겨(5 는 1.0, 2~4 는 0.5, 1 은 0.0) 옛 라벨과 몇 건이 같은지 센다. 같은 사람이 같은 사례를 두 번 매긴 결과이므로, 이 수치는 사람 라벨이 얼마나 흔들리는지를 보여준다. 옮기는 규칙은 옛 라벨의 정의(근거에 없는 주장이 하나라도 있으면 1.0 이 아니다)를 따른다. 이 수치는 판정에 쓰지 않는다.

### 4-7. 점수 읽는 규칙

모델 출력에서 점수를 읽는 규칙도 측정 전에 고정한다. 2026-10-02 에 사용자가 결정했다. 원칙은 "꾸밈은 너그럽게, 값은 엄격하게" 다.

읽은 결과는 상태 넷 중 하나다. 앞의 하나만 점수가 있고, 나머지 셋은 모두 못 읽음이지만 서로 다른 칸으로 센다.

| 상태 | 뜻 |
|---|---|
| ok | 1~5 정수 점수 하나를 읽었다 |
| missing | `[RESULT]` 가 없다. 출력이 잘렸거나 양식을 따르지 않았다 |
| out_of_range | `[RESULT]` 는 있지만 1~5 정수로 읽을 수 없다(범위 밖, 소수, 음수, 다른 글자). 예: `[RESULT] 7`, `[RESULT] 4.5`, `[RESULT] 4.0`, `[RESULT] -1`, `[RESULT] Score: 4`, `[RESULT] 4/10`(만점이 5가 아닌 분수), `[RESULT]` 뒤에 아무것도 없음 |
| conflict | `[RESULT]` 를 여러 번 쓰고 값이 서로 다르다 |

너그럽게 받는 꾸밈은 셋이다. `[RESULT]` 앞뒤의 마크다운 굵게(`**[RESULT]** 4`, `[RESULT] **4**`), `[RESULT]` 뒤의 콜론 하나(`[RESULT]: 4`), 점수를 감싼 괄호(`[RESULT] (4)`)다. 숫자 모양의 차이도 꾸밈으로 본다: 전각 숫자(`[RESULT] ４` 는 4), 5점 만점 분수(`[RESULT] 4/5` 는 4), 앞의 0(`[RESULT] 05` 는 5). 이 셋은 2026-10-02 에 출력을 보기 전에 정했다. 분모는 `/` 로 쓴 것만 본다. `[RESULT] 4 out of 10` 이나 `[RESULT] 4점 (10점 만점)` 처럼 글로 쓴 분모는 잡지 않아 4 로 읽힌다. 지시문이 1~5 정수를 요구하므로 드물 것으로 보고 규칙을 넓히지 않았다. 결과에서 이런 출력이 보이면 결과 문서에 적는다. 일반 지시 모델은 이런 꾸밈을 흔히 붙인다. 이것 때문에 못 읽음이 되면 실력과 무관하게 4-4절의 "못 읽음 0건" 에서 떨어진다.

값은 엄격하게 본다. 소수를 정수로 잘라 읽으면 모델이 쓰지 않은 점수를 우리가 만든다. 같은 점수를 여러 번 쓴 것은 ok 다(모순이 아니다).

숫자가 없는 `[RESULT]` 는 다른 `[RESULT]` 에 읽을 값이 있으면 무시한다. 모델이 지시문의 "`[RESULT] (an integer number between 1 and 5)`" 를 따라 쓴 뒤 진짜 점수를 쓰는 경우를 살리려는 것이다. 읽을 값이 어디에도 없을 때만 out_of_range 다.

missing 은 "`[RESULT]` 자체가 없다" 하나로만 둔다. 그래야 missing 이 잘림과 양식 불이행을 가르는 칸으로 남는다. `[RESULT]` 는 썼지만 뒤의 값을 읽을 수 없는 출력을 out_of_range 로 보내는 것은 새 결정이 아니라, 사용자가 승인한 원칙("값이 이상한 것은 못 읽음, 꾸밈은 허용")을 적용한 것이다. 첫 구현이 이 경우를 missing 으로 세던 것을 리뷰에서 찾아, 모델 출력을 보기 전에 고쳤다(2026-10-02).

보고서는 못 읽음 중 최대 출력(512 토큰)에서 잘린 사례 수를 따로 적는다. missing 만 세지 않는 이유는 `[RESULT]` 직후에 잘린 출력이 out_of_range 가 되기 때문이다. 판정에서는 그대로 못 읽음으로 센다.

### 4-8. 호출에 끝내 실패한 사례

모델 호출이 오류를 내거나 빈 응답을 돌려준 사례는 결과로 쓰지 않고 다시 부른다. 다시 불러도 결과를 받지 못한 사례가 남으면, 그 모델의 결과가 44건이 되지 않으므로 **보고서를 만들지 않는다.** 그 사례를 빼고 계산하는 규칙은 두지 않는다. 실제로 생기면 사람이 사례를 보고 따로 정한다. 2026-10-02 에 사용자가 결정했다.

이렇게 정한 이유: 빼고 계산하는 규칙을 미리 두면, 어느 사례가 빠졌는지에 따라 결과가 유리하게 바뀔 수 있다. 다시 부르면 대부분 풀릴 것으로 보고, 풀리지 않는 드문 경우에만 사람이 판단한다.

## 7. 이 실험 다음 단계의 후보 (이번에 하지 않는다)

M4 를 직접 채점 학습시키는 것이다. 사람이 학습 데이터를 매기지 않고 만드는 방법을 이번에 정리해 둔다.

- 새 라벨이 5 인 답변을 가져와 일부러 망가뜨린다. 숫자를 바꾸거나 근거에 없는 문장을 하나 넣는다. 망가뜨린 방식을 우리가 알기 때문에 정답 점수도 안다(문장 하나 추가는 4, 전부 바꾸면 1). 따라서 학습 데이터를 수백 건 이상 자동으로 만들 수 있다.
- 시험은 이 실험의 44건처럼 실제 생성 답변에 사람이 매긴 라벨로 본다. 일부러 망가뜨린 답변은 실제 생성 모델의 실수와 모양이 다를 수 있다. 따라서 시험까지 자동으로 만들면 우리가 상상한 실수만 잘 잡는다는 것을 확인하게 된다.
- 44건은 시험에만 쓴다. 학습에 쓰면 시험을 볼 수 없다.

## 8. 한계

- 사례 44건, 봇 하나, 코퍼스 하나다.
- 새 라벨을 매기는 사람은 옛 라벨을 매긴 사람과 같다. 화면에서 옛 라벨을 숨겨도 기억이 남아 있을 수 있다. 따라서 새 라벨은 완전한 블라인드가 아니다.
- 사람과 모델이 같이 틀린 사례는 이 대조로 잡히지 않는다.
- 코랩 모델은 모두 4비트다. 원래 정밀도에서의 성능은 재지 않는다.
- 공통 지시문의 틀은 M3 가 학습한 양식이다. 따라서 M3 에 유리할 수 있다. 다른 모델에게는 낯선 양식이지만, M1, M2, M4 는 일반 지시 모델이라 낯선 양식도 따르도록 학습됐다.
- 이 실험의 M1 점수는 공통 지시문으로 매긴 것이다. 서비스에서 M1 이 매기는 점수와 같은 값이 아니다(3-2절).
- 결과는 이 시점의 모델 리비전 기준이다.
