## ① 설명 문구 3개 삭제

대시보드 9개 화면의 `PageHeader description` 을 두 부류로 나눴다.

| 부류 | 화면 | 처리 |
|---|---|---|
| **내부 동작을 안심시키는 문구** — 읽어도 사용자가 할 일이 없다 | 내 봇("봇 단위로 격리됩니다…") · 문서 관리("올린 문서만 근거가 됩니다…") · 봇 설정("봇 이름과 문구를 관리합니다" — 제목과 같은 말) | **삭제** |

지운 문구를 근거로 삼는 주석이 있으면 함께 정리한다.

검토한 대안: 격리 문구 한 줄만 삭제(나머지 두 개도 같은 부류라 반쪽 처리) · 9개 전부 삭제("품질 지표에서 제외" 같은 안내까지 사라진다).

## ② 헤더 잇기

막힌 곳이 둘이다.

1. 대시보드 헤더(`app/(dashboard)/layout.tsx`)에 `/`(랜딩)로 가는 링크가 없다. 로고도 `/dashboard` 로 간다.
2. 마케팅 헤더(`app/(site)/layout.tsx`)는 로그인한 뒤에도 "로그인" 버튼만 보인다.

**고치는 방법**

- 대시보드 헤더: "결제 수단" 왼쪽에 `소개` 링크(→ `/`) 하나. 랜딩에 이미 "기능" 메뉴가 있고
  기능 페이지 상단에서 요금제·FAQ 로 이어지므로 링크 하나면 전부 닿는다.
- 마케팅 헤더: 고정 "로그인" `<Link>` 를 새 클라이언트 컴포넌트 `components/AuthLink.tsx` 로 교체.
  토큰이 있으면 "대시보드"(→ `/dashboard`), 없으면 "로그인"(→ `/auth`).

**왜 컴포넌트를 떼어내는가** — 토큰이 `localStorage` 에만 있어 서버 컴포넌트인 레이아웃은 읽을 수 없다.
봇 이름(`BotName`)을 같은 이유로 뗀 선례를 따른다. 토큰 구독은 대시보드 레이아웃이 쓰는
`useSyncExternalStore` 세 함수(`subscribeAccessToken` · `getAccessToken` · `getAccessTokenServerSnapshot`)를 그대로 쓴다.

**첫 렌더는 "로그인"이다.** 서버 스냅샷이 `undefined`(아직 모름)라 서버 HTML 과 첫 클라이언트 렌더가
"로그인"으로 일치하고, 하이드레이션 뒤 토큰을 읽어 "대시보드"로 바뀐다. 로그인한 사람에게만
한 프레임 깜빡임이 있다 — 하이드레이션 불일치를 내지 않는 유일한 방법이라 받아들인다.

검토한 대안: 대시보드 헤더에 기능·요금제·FAQ 메뉴 복제(메뉴가 두 벌이 되고 "로그인" 문제는 어차피 따로 고쳐야 한다).

## ③ 루트 글자 18px

본문 대부분이 14px(`text-sm`, 128곳)이고 보조 글자가 12px(`text-xs`, 109곳)이다. 한국어 UI 로 작다.

Tailwind 는 크기를 전부 루트 글자 크기 배율(rem)로 계산한다. `globals.css` 에
`html { font-size: 18px; }` 한 줄을 두면 237곳을 안 건드리고 전체가 12.5% 비례 확대된다.
여백·카드 폭도 같이 커져 "확대"한 것처럼 균형이 유지된다 (본문 14 → 15.75px · 보조 12 → 13.5px · 콘텐츠 최대 폭 1152 → 1296px).

**안 변하는 것**: 랜딩 히어로 장면은 px 고정값이라 그대로다.
**같이 움직이는 것**: Tailwind 반응형 경계(`sm:` = 40rem)도 640 → 720px 로 옮겨간다. 관리자 화면은
데스크톱 전용이라 영향 없다. **위젯 페이지(`/w/[publicKey]`)는 같은 루트를 쓰므로 함께 커진다** —
브라우저로 확인하고 너무 크면 위젯 레이아웃에서만 되돌리는 방법을 그때 제안한다.

검토한 대안: 17px(6% — "키웠나?" 싶은 정도) · 글자 토큰(`--text-sm` 등)만 재정의(여백이 안 늘어 빽빽해지고 토큰 6개를 따로 손본다).
