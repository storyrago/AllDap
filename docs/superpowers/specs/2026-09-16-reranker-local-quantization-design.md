# 리랭커 로컬 실행 + 양자화 (설계)

2026-09-16 | 범위: `ai-service` 안. Spring · `web/` · `widget/` 은 건드리지 않는다.

## 한 줄 요약

지금 Cloudflare API 로 부르는 리랭커(`bge-reranker-base`)를 **내 컴퓨터에서 직접 돌리고,
그것을 양자화해서 얼마나 작아지고 얼마나 나빠지는지 기존 평가 16문항으로 잰다.**

---

## 1. 왜 지금 이것인가

### 1-1. 하려는 일이 저장소 규칙과 충돌한다. 규칙을 고치고 간다

`AGENTS.md` 7번과 `docs/BACKLOG.md` §7 이 **모델 경량화 · 양자화 · 온디바이스 추론을
"하지 않기로 결정한 것"** 으로 못박아 두었다. 기각 사유는 이랬다.

> 지금 끌어들이면 Python 학습 · Spring 구현 · 경량화가 **전부 어중간해진다.**

🔴 **그 사유의 전제가 바뀌었다.** 그 문장은 프로젝트가 미완일 때 쓴 것이다.
지금은 W1~W4 가 끝났고, 배포 · 결제 · 부하테스트가 끝났고, Swagger 는 의도적으로 멈췄다.
`BACKLOG.md` 에 남은 항목은 대부분 트리거가 **"실사용자가 생기면"** 이다.
**어중간해질 대상이 남아 있지 않다.**

그래서 이 슬라이스는 규칙을 **어기는** 것이 아니라 **고치는** 것이다.
§7 에 그 절차를 적었다. 몰래 하면 문서끼리 어긋나고, 이 저장소가 반복해서 당한 실패가
정확히 그것이다(**"고쳤는데 그것을 설명하는 자리를 안 고친 것"**).

### 1-2. 겨냥하는 실제 문제가 있다

`BACKLOG.md` §5 에 이렇게 적혀 있다.

> **리랭커가 정답을 밀어내는 실패 2건.** 재택 · 기간제. 순위 융합(`rerank_fusion`)으로
> 풀려다 **반증됐다.** 풀려면 "언제 리랭커를 믿을지" 를 아는 신호가 필요하다.

🔴 **지금 리랭커는 이 저장소의 문서를 한 번도 본 적이 없다.** 남이 일반 데이터로 학습시킨
것을 그대로 쓴다. "취업규칙" 과 "계약직 운영지침" 중 무엇이 정답인지 알 이유가 없다.

**이 문제를 겨냥하는 것은 파인튜닝(3단계)이고, 이번 슬라이스는 그 선행 배관이다.**
리랭커를 로컬에서 돌리지 못하면 파인튜닝한 모델을 쓸 자리가 없다.

### 1-3. 배포는 이 슬라이스의 명분이 아니다

t3.micro 는 1GB 이고 원본 리랭커는 약 1.1GB 라 **절대 안 들어간다.**
양자화하면 약 280MB 라 **들어갈 수도 있다.**

⚠️ **그러나 그것은 보너스이지 명분이 아니다.** AllDap 은 EC2 + RDS + Vercel + 자동배포 +
부하테스트까지 이미 끝냈다. **배포 축은 이미 증명됐으므로 여기서 다시 증명할 것이 없다.**
재는 것(얼마나 줄고, 얼마나 빨라지고, 품질이 얼마나 유지되나)은 맥북에서 재도 유효하다.

## 3. 설계

### 3-1. 이음매는 제공자 파일 하나

이 저장소에는 이미 선례가 있다. `friendli.py` 주석이 그 규칙을 적어 두었다.

> `cf.py` 는 <Cloudflare 를 어떻게 부르는가>만 아는 파일이다. 그 안에 두 번째 제공자를
> 끼워 넣으면 "어느 분기가 어느 제공자였더라" 가 시작된다.
> **제공자마다 파일을 하나씩 두고, 부르는 쪽이 고른다.**

그대로 따른다.

```
app/local_reranker.py   새 파일. ONNX Runtime 으로 로컬 추론
app/retriever.py        _rerank 안에서 설정값 하나로 제공자를 고른다
app/config.py           reranker_provider: "cloudflare" | "local" | "local_int8"
```

**출력 계약을 Cloudflare 와 똑같이 맞춘다.** 지금 `_rerank` 가 기대하는 모양이 이것이다.

```python
{"response": [{"id": <입력 인덱스>, "score": float}, ...]}   # 점수 내림차순
```

로컬 구현도 같은 모양을 돌려주면 **`_rerank` 의 나머지 로직(실패 시 원래 순서 유지,
빠진 인덱스 보전, `rerank_fusion`)을 한 줄도 안 고쳐도 된다.**

⚠️ **실패 시 원래 순서를 유지하는 성질을 반드시 보존할 것.** `_rerank` 주석이 적어둔 대로
리랭커는 부가 기능이고, **리랭커가 죽었다고 채팅이 죽으면 안 된다.**
로컬 추론은 Cloudflare 와 실패 모드가 다르다(모델 파일 없음 · 메모리 부족 · 스레드 고갈).
새 실패 모드가 늘어나는 것이므로 `try/except` 를 더 넓게 잡는다.

### 3-2. 실행 방식은 ONNX Runtime

| 후보 | 채택 | 이유 |
|---|---|---|
| **ONNX Runtime** | ✅ | CPU 추론에 맞춰진 런타임. **동적 양자화(INT8)가 내장**이라 별도 도구가 없다. 런타임 패키지가 작다 |
| PyTorch + transformers | ❌ | 런타임 의존성이 2GB 대다. 추론만 하는데 학습 프레임워크를 통째로 싣는다 |
| llama.cpp / GGUF | ❌ | 생성 모델(LLM)용 생태계다. BERT 계열 리랭커는 주 대상이 아니다 |

🔴 **변환할 때만 torch 가 필요하고, 돌릴 때는 필요 없다.** 이 분리가 중요하다.
모델을 ONNX 로 내보내는 것은 **한 번만** 하면 되고, 그 산출물을 돌리는 데는
`onnxruntime` 하나면 된다.

### 3-3. 의존성은 `requirements.txt` 에 넣지 않는다

🔴 **별도 파일 `ai-service/requirements-lab.txt` 로 가른다.**

이유는 이 저장소가 `prometheus-fastapi-instrumentator` 를 기각하며 적어둔 것과 같은
계열이다. **운영 이미지에 실험용 의존성을 싣지 않는다.**
`ai-service/Dockerfile` 이 `requirements.txt` 를 읽고, 그 이미지를 1GB 짜리 t3.micro 가
받는다. torch 를 넣으면 이미지가 수 GB 늘고 **실험이 운영 배포를 무겁게 만든다.**

```
requirements.txt        (건드리지 않는다)
requirements-lab.txt    onnxruntime · optimum[exporters] · transformers · torch
```

⚠️ **그 결과 `reranker_provider="local"` 은 운영 이미지에서 기동하지 않는다.**
의도한 것이다. 기본값은 `"cloudflare"` 로 두고, 로컬 제공자를 골랐는데 `onnxruntime`
이 없으면 **조용히 Cloudflare 로 떨어지지 말고 명확한 한국어 오류를 낼 것.**
(`friendli.py` 가 토큰 없을 때 하는 것과 같다. 조용히 건너뛰면 "무엇을 쟀는지" 를 잃는다)

### 3-4. 모델 파일은 저장소에 커밋하지 않는다

원본 약 1.1GB · INT8 약 280MB 다. git 에 넣을 크기가 아니다.

```
ai-service/models/              .gitignore 에 추가
ai-service/app/export_reranker.py   내려받기 → ONNX 변환 → INT8 양자화까지 한 스크립트
```

⚠️ **`testdata/fixtures/` 와는 판단이 다르다.** 거기는 바이너리를 커밋했고 그 이유가
*"돌릴 때마다 바이트가 달라지면 파서가 회귀했는지 생성기가 달라졌는지 구분할 수 없다"*
였다. **모델 가중치는 그 문제가 없다.** 같은 리비전을 받으면 같은 바이트가 온다.
따라서 스크립트에 **모델 리비전을 못박는다.** 태그 없이 받으면 나중에 다른 가중치가 와서
"양자화 때문인가 모델이 바뀐 것인가" 를 구분할 수 없게 된다.

### 3-5. 양자화 방식

**동적 양자화(dynamic quantization) INT8** 로 시작한다.

- 가중치를 8비트 정수로 줄이고, 활성값은 추론 중에 그때그때 양자화한다
- **보정 데이터(calibration set)가 필요 없다.** 정적 양자화는 대표 입력 표본이 필요한데,
  그것을 고르는 순간 **표본 선택이 결과에 섞인다.** 변수를 하나만 바꾸려면 없는 쪽이 낫다
- BERT 계열 인코더에서 가장 많이 쓰이는 기본 경로다

⚠️ 정적 양자화 · INT4 는 이번 범위가 아니다. 동적 INT8 이 기대만큼 안 나오면 그때 본다.

## 4. 측정 계획

### 4-1. 무엇을 재나

**기존 평가를 그대로 쓴다.** 새 도구를 만들지 않는다. 16문항 · 50문서 · 306청크 ·
`temperature=0` · 리랭커 + 하이브리드 ON 이 지금 기본값이고, 그 위에서 리랭커 제공자만 바꾼다.

| 설정 | 리랭커 | 무엇을 아는가 |
|---|---|---|
| **A** | Cloudflare (현행) | 기준선 |
| **B** | 로컬 원본 (ONNX fp32) | **같은 모델인데 결과가 같은가** |
| **C** | 로컬 양자화 (ONNX INT8) | **얼마나 줄고 얼마나 나빠지는가** |

🔴 **B 가 이 표의 핵심이다.** B 를 건너뛰고 A 와 C 만 비교하면, 차이가 생겼을 때
**양자화 탓인지 실행 환경 탓인지 구분할 수 없다.** 이 저장소가 여덟 번 낸 버그가 전부
**"원인이 다른 사실들을 같은 값으로 뭉갠 것"** 이었다. 같은 함정을 미리 가른다.

**A 와 B 가 다르게 나오는 것 자체가 결과다.** 같은 이름의 모델이라도 Cloudflare 가
무엇을 돌리는지 우리는 모른다(가중치 리비전 · 내부 양자화 여부 · 전처리).

### 4-2. 재는 값

| 축 | 지표 | 출처 |
|---|---|---|
| 품질 | **전체 충실성** · 관련성 · 응답률 | 기존 평가 대시보드 |
| 품질 | **회당 오답 · 회당 완전오답 · 회당 fallback** | 기본값을 정할 때 쓴 지표. 평균보다 결정적이었다 |
| 품질 | **문항별 표** (특히 재택 · 기간제 · 영문증명서) | 평균이 같아도 내용물이 다른 것을 네 번 겪었다 |
| 속도 | 채팅 지연 (현행 1.56초) | |
| 크기 | 모델 파일 바이트 | |
| 메모리 | 추론 중 RSS 최대치 | t3.micro 판단의 재료 |
| 비용 | Cloudflare 뉴런 (현행 리랭커 13.6 / 회) | `cf._record_neurons` |

### 4-3. 반복 횟수

🔴 **설정당 3회 이상.** `AGENTS.md` 가 실측으로 정한 규칙이다.

> `temperature=0` 인데도 편차 폭이 **0.032** 다. 그보다 작은 개선은 노이즈와 구별되지 않는다.

**즉 이 실험에서 0.032 보다 작은 차이는 "같다" 로 읽는다.**
양자화가 품질을 조금 떨어뜨릴 것으로 예상하는데, 그 폭이 0.032 안이면
**"나빠졌다" 가 아니라 "구별되지 않는다" 가 정확한 서술이다.**

### 4-4. 비용

평가 1회가 804 뉴런이고 하루 한도가 10,000 이라 **하루 12회**다.
설정 3개 × 3회 = 9회이므로 **하루 안에 끝난다.**

⚠️ 단 B · C 는 리랭커를 로컬에서 돌리므로 그 13.6 뉴런이 빠진다. 총량이 줄지 늘지는 않는다.

## 5. 위험과 한계 (미리 적는다)

| | |
|---|---|
| 🔴 **로컬에서 잰 속도는 운영 속도가 아니다** | 개발 기계는 Apple M4 Pro(ARM)이고 EC2 는 x86_64 다. **INT8 가속은 아키텍처마다 다르다.** 속도 수치에는 반드시 "M4 Pro 기준" 을 붙일 것. 운영 속도를 알려면 거기서 재야 한다 |
| 🔴 **t3.micro 투입 여부는 이 슬라이스로 알 수 없다** | 280MB 는 모델 파일 크기이고, 실제 상주 메모리는 런타임 · 스레드 · 배치에 따라 더 크다. 1GB 에 이미 Spring · Caddy · Python 이 올라가 있다. **"들어갈 수도 있다" 이상을 주장하지 말 것** |
| ⚠️ **16문항은 작다** | 한 문항이 0.0625 를 움직인다. 편차 0.032 와 겹치는 크기다. 코퍼스는 50문서지만 테스트셋은 16문항 그대로 둔다(회당 비용이 문항 수에 정비례한다) |
| ⚠️ **리랭커는 이미 기본값으로 켜져 있다** | 이 실험은 꺼진 기능을 켜는 것이 아니라 **켜져 있는 경로를 갈아 끼우는 것**이다. 잘못되면 지금 지키고 있는 **회당 오답 0건**이 깨진다. 기본값은 실험 내내 `"cloudflare"` 로 두고, 측정할 때만 바꾼다 |
| ⚠️ **Cloudflare 가 무엇을 돌리는지 모른다** | `@cf/baai/bge-reranker-base` 가 원본 그대로인지, 자기들이 이미 양자화한 것인지 공개돼 있지 않다. **그래서 B 를 잰다.** 이 불확실성 자체가 측정으로만 좁혀진다 |

## 6. 🔴 다음 단계 (여기 못박아 둔다)

**리랭커 파인튜닝.** 이 슬라이스는 그 선행 배관이며, 배관만 깔고 끝내지 않는다.

| | |
|---|---|
| **겨냥하는 것** | `BACKLOG.md` §5 의 **"리랭커가 정답을 밀어내는 실패 2건"**(재택 · 기간제). `rerank_fusion` 으로 풀려다 제로섬인 것이 **반증됐다.** 남은 길이 이것이다 |
| **왜 가능한가** | `bge-reranker-base` 는 2억 7천만 파라미터라 **M4 Pro 24GB 에서 학습된다. GPU 를 빌리지 않는다** |
| **학습 데이터** | `evaluator.make_question` 이 이미 (질문, 정답) 쌍을 청크에서 생성한다. 정답 청크가 positive, 같은 질문에 검색됐지만 틀린 청크가 negative 다. **합성 데이터 생성 장치가 이미 있다** |
| 🔴 **순서** | **파인튜닝 → 양자화**, 즉 **학습을 먼저 하고 나중에 줄인다.** QLoRA 처럼 줄여놓고 학습하는 것은 **메모리가 모자랄 때의 타협**이고 우리는 모자라지 않다. 그리고 학습 결과를 원본으로 갖고 있어야 **양자화 강도를 바꿔가며 여러 번 잴 수 있다** |
| **이 슬라이스가 남기는 것** | ②에서 만든 양자화 스크립트를 파인튜닝 뒤에 **한 번 더 돌리면 된다.** 버리는 코드가 없다 |

**최종 측정표는 이렇게 완성된다.**

| | 리랭커 | 슬라이스 |
|---|---|---|
| A | Cloudflare (현행) | 이번 |
| B | 로컬 원본 | 이번 |
| C | 로컬 양자화 | 이번 |
| D | 로컬 파인튜닝 | 다음 |
| E | 로컬 파인튜닝 + 양자화 | 다음 |

## 8. 완료 조건

이 슬라이스는 아래가 **전부 실측으로** 확인될 때 끝난다.

1. `reranker_provider="local"` 로 채팅이 동작하고, **근거와 출처가 지금과 같은 모양으로 나온다**
2. 모델 파일이 없을 때 **조용히 Cloudflare 로 떨어지지 않고 한국어 오류를 낸다**
3. 로컬 추론이 실패해도 **채팅이 죽지 않고 원래 순서를 유지한다** (`_rerank` 의 기존 성질)
4. A · B · C 를 **각각 3회 이상** 돌린 결과표 (§4-2 의 모든 축)
5. 그 결과를 `AGENTS.md` 에 한 절로 남긴다. **A 와 B 가 달랐다면 그 사실을 숨기지 않는다**
6. §7 의 문서 셋이 함께 고쳐졌다

⚠️ **4번에서 "재현되지 않았다" 가 나오면 그것도 결과다.** 이 저장소는 리랭커를 두 번,
하이브리드를 한 번, 융합을 한 번 **기각한 기록**을 갖고 있다. 양자화가 품질을 눈에 띄게
떨어뜨리면 **기본값을 바꾸지 않고 측정만 남긴다.** 코드는 지우지 않는다
(`rerank_fusion` 을 남긴 것과 같은 이유다. 지우면 재현할 수 없는 주장이 된다).
