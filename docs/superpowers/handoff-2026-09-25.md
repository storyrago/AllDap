## 2. 결론 (수치 전문은 `AGENTS.md` "채점자를 사람 라벨과 대조했다 (2026-09-25)" 절)

```
일치 40건 (90.9%)  ·  채점자 후함 2  ·  박함 2  ·  선형가중 카파 0.509
전체충실성 왜곡량   306청크 -0.0577  /  360청크 +0.0000 ~ +0.0192
```

**① 1차(블라인드)와 최종의 차이는 채점자가 아니라 <기준>이었다.**
1차는 일치 68.2% · 후함 12건 · 왜곡 -0.1538 이었다. 불일치 14건의 메모를 읽어보니 감점 사유의
절반 가까이가 충실성 밖이었다(표현 · 사용성 · 답변이 덜 옮긴 것). 사람이 깎은 14건 전부를
같은 기준으로 다시 보게 한 뒤 40건 일치가 됐다.
🔴 **두 수치를 <둘 다> 남겼다.** 1차는 블라인드라서, 최종은 기준이 정리돼서 각각 값어치가 있다.

**② 2026-09-18 의 "코퍼스가 난이도가 아니라 채점을 때렸다" 가 독립적으로 뒷받침됐다.**
306 → 360 청크에서 **채점자 기준 -0.0577, 사람 기준 +0.0128** 로 방향이 반대다.

**③ 설정 비교표는 살아남는다. 단 같은 코퍼스 안에서만이다.**
같은 코퍼스 위의 A·B 비교는 왜곡이 양쪽에 공통으로 실려 상쇄된다. **코퍼스를 가로지르는
비교는 계속 위험하다** (왜곡 자체가 -0.0577 ↔ +0.0192 로 코퍼스마다 다르다).

**기록한 자리 넷**: `AGENTS.md` 새 절 · `ai-service/app/judge.py` 첫머리(2026-08-02 부터
달려 있던 "아직 사람 라벨과 대조하지 않았다" 를 수치로 교체) · `docs/BACKLOG.md` §5 카파 항목 ·
`docs/decisions.md` 2026-09-25 항목.

## 3. 만든 것 (라벨링 화면)

```
cd ai-service
.venv/bin/python -m app.judge_label_server      # http://127.0.0.1:8765
.venv/bin/python -m app.judge_agreement report  # 혼동행렬 · 방향 · 왜곡량 (외부 API 안 부름)
.venv/bin/python -m app.judge_agreement report --reasons   # 불일치분만 재호출 (약 25 뉴런/건)
```

| 결정 | 이유 |
|---|---|
| **DB 에 안 붙는다** | 읽는 것은 라벨 파일뿐이고 거기에 채점자 점수가 없다. **블라인드를 코드가 아니라 데이터가 지킨다** |
| **표준 라이브러리만** | 보조 도구 때문에 `requirements.txt` 가 늘면 안 된다 |
| **127.0.0.1 바인딩** | 이 파일에는 코퍼스 본문(청크 전문)이 들어 있다 |
| **임시 파일 + `os.replace`** | 라벨링 중간에 죽어도 반쯤 쓰인 JSON 이 남지 않는다 |
| 🔴 **문장 분할은 <글자> 기준** | LLM 에게 주장을 뽑게 하면 사람 기준자가 보는 목록이 LLM 산출물이 되어 대조가 무의미해진다. 그래서 한 문장에 정보가 둘이면 여전히 사람이 더 쪼갠다 |

## 4. 🔴 이 슬라이스가 남긴 방법론 (다음에 같은 일을 할 때 그대로 쓸 것)

**① 재검토 대상을 <불일치 건>으로 고르면 안 된다.** 불일치만 다시 보면 고칠 때마다 일치
쪽으로만 움직여 "채점자와 맞춰주는 작업" 이 된다. **사람이 깎은 건 전부**처럼 채점자와 무관한
기준으로 골라야 한다(이번에 그중 4건은 이미 채점자와 일치하던 것이었다).

**② 라벨 눈금을 채점자보다 세밀하게 만들면 안 된다.** 사람이 0.75 를 주면 채점자는 그 칸에
올 수가 없어, 불일치가 "채점자가 틀렸다" 가 아니라 **"둘이 다른 자로 쟀다"** 가 된다.

**③ 사람에게 기준을 글로 주는 것만으로는 부족했다.** 화면의 `_readme` 를 그대로 띄웠더니
"0.5 가 무슨 뜻인가" 와 "근거 개수를 세는 것이 아니다" 가 전달되지 않았다. 표 + 예시 +
"답변 → 근거 한 방향" 명시로 고쳤다. **기준 문서를 고치는 것도 측정 도구를 고치는 일이다.**

## 5. ⬜ 다음 슬라이스: 무관한 청크 주입 탐침

언제 눈이 머는지 본다. 배관(`app/eval_cases.py`)은 이미 있고 채점 호출 수십 회 ≈ 700 뉴런이다.

🔴 **사람 라벨이 나온 지금이 할 때다.** 그 왜곡이 얼마나 되는지는 기준선이 있어야 말할 수 있다.

🔴 **이 트랙은 평가 도구 개선을 넘어선다.** 채점자와 생성 모델은 **같은 근거 목록**을 받는다.
생성 쪽까지 재면 **검색 설정(`top_k` · `max_distance`)의 근거**가 된다. 2026-09-18 에
"top_k 에 무관한 청크가 끼는 것은 무해하다" 는 전제가 이미 깨졌다.

**그 뒤 후보** (`docs/BACKLOG.md` 참고)
- 경쟁 분석에서 확인 못 한 둘 (§6-1). 자소서 · 면접 · 블로그에 차별점을 쓰기 <전에> 닫을 것
- 난이도 확보 (§5). 문서와 질문을 **같이** 바꿔야 한다는 것이 2026-09-18 의 결론이다

## 6. 🔴 다음 사람이 밟을 함정

- 🔴 **`eval_set load --replace` 를 돌리지 말 것.** `eval_results` 156행이 CASCADE 로 날아가고
  이 대조의 재료가 사라진다. 누르기 전에:
  `docker exec -i alldap-db pg_dump -U alldap alldap -t eval_questions -t eval_runs -t eval_results --data-only`
- **사람 라벨은 `ai-service/testdata/judge_labels.json` 에 있다. 파일은 <최종 상태>만 갖는다.**
  1차(블라인드) 집계는 `AGENTS.md` 표에만 있다. 라벨을 덮어쓰면 그 비교를 되살릴 수 없다.
- **카파 0.509 를 단독으로 인용하지 말 것** (카파 역설. 44건 중 40건이 한 칸에 몰려 있다).
- **`report` 는 덜 채운 라벨로는 실행되지 않는다.** 부분 집계를 내지 않는 것이 의도다.
- **봇은 1번이다.** 청크가 있는 봇이 셋이라 도구들이 자동 선택을 거부하고 `EVAL_BOT_ID` 를 묻는다.
- **실행**: `docker compose up -d` 뒤 이 슬라이스의 도구들은 **uvicorn 없이 DB 만으로 돈다.**
