## 결론

**학습 전 M3 와 학습 후 M3 의 비교는 두 시험지 모두 "학습 후 M3 가 대응표에 더 가깝다" 다. 학습 후 M3 는 교체 후보다.** (출처: report.md)

- 새 시험지(120문항): 학습 후 M3 가 더 가까운 문항 28개, 학습 전 M3 가 더 가까운 문항 0개, 같음 92, 제외 0, p = 0.0000.
- 동결 시험지(231문항): 학습 후 M3 가 더 가까운 문항 48개, 학습 전 M3 가 더 가까운 문항 15개, 같음 168, 제외 0, p = 0.0000.
- 심각한 놓침: 새 시험지에서 학습 전 M3 12개가 학습 후 M3 1개로, 동결 시험지에서 5개가 1개로 줄었다. M1 은 새 시험지에서 실행마다 1, 2, 1개, 동결 시험지에서 1개다.
- 스펙 8-4절의 기준 넷을 모두 통과했다(6-4절).
- 학습 후 M3 와 M1 의 비교(기준에 쓰지 않는다)도 두 시험지 모두 "학습 후 M3 가 대응표에 더 가깝다" 다. 새 시험지 21 대 5, p = 0.0025. 동결 시험지 55 대 27, p = 0.0026.

이 결과는 **대응표와 맞는가**에 대한 답이다. 정답 점수가 사람의 판단이 아니라 변형 유형에서 정해졌기 때문이다(스펙 11절). **교체 후보가 나왔지만 서비스의 채점 모델은 바꾸지 않는다.** 교체를 어떻게 할지는 별도 결정이다(스펙 2-2절, 8-4절).

- **모범 답안이 문장 틀이라 말투가 굳을 위험이 있다.** 이유의 다양성은 재지 않았다.
- **⑧ 이외 유형의 학습 효과는 측정 대상이 아니다.** 6-6절의 유형별 관찰은 판정에 쓰지 않는다.
- **프롬프트 수정으로 같은 효과를 얻을 수 있었는지 알 수 없다.**
- **학습 설정은 흔한 시작값이고 한 번만 학습했다.** 이번에는 기준을 통과했지만, 다른 설정이 더 나았는지는 모른다.
- **학습 데이터는 검수하지 않았다.** 글자 확인만 했고, 학습 데이터 리뷰는 계획대로 표본 확인이었다. 전수 대조는 하지 않았다. 표본에서 1건(`travel-130`)을 찾아 고쳤으므로, 표본 밖에 같은 오류가 남아 있을 수 있다(2-3절).
- **④ 의 정답 점수 결함을 이어받는다.** 학습 데이터의 ④ 34문항은 애매한 문항에 3점을 가르친다.
- **정답 점수는 대응표다.** 이 결과는 대응표와 맞는가까지만 말한다. 사람과 비슷한가는 말하지 않는다.
- **출제와 학습 데이터, 모범 답안이 모두 Claude 에서 나온다.** Claude 가 상상한 실수의 모양을 배웠다.
- **M1 의 반복 횟수가 시험지마다 다르다.** 동결 시험지 1회(v2), 새 시험지 3회. 새 시험지에서 M1 은 실행마다 값이 달랐으므로(3-2절), 동결 시험지의 M1 값도 실행마다 다를 수 있다.
- **학습 후 M3 의 동결 시험지 결정성은 새 시험지의 확인에서 미루어 본 것이다.**
- **체크포인트에서 이어 한 학습은 끊기지 않은 학습과 비트 단위로 같다는 보장이 없다.** 이번 학습은 끊기지 않아(끊긴 횟수 0) 해당하지 않는다.
- **코랩 모델은 모두 4비트다.** 공통 지시문이 M3 가 학습한 양식이라 M3 에 유리할 수 있고, 이 실험의 M1 점수는 서비스의 M1 점수와 같은 값이 아니다.
- **결과는 이 시점의 모델 리비전, 검색 설정, 라이브러리 판 기준이다.**

### 8-2. 실행하면서 새로 알게 된 한계

- **새 시험지와 학습 데이터는 분야만 다르고 만드는 방법은 같다.** 같은 변형 유형, 같은 출제 방식, 같은 공통 지시문이다. 동결 시험지도 v2 의 같은 방식에서 나왔다. 그래서 학습 후 M3 가 이 방식으로 만든 잘못된 답변을 잘 잡게 된 것인지, 다른 방식으로 생긴 실수(실제 답변 생성 모델의 실수)에도 이어지는지는 이 실험으로 말할 수 없다. 두 시험지에서 모두 좋아진 것은 분야를 넘어 이어졌다는 근거이지, 만드는 방법을 넘어 이어졌다는 근거는 아니다.
- **코랩이 실험 도중 python 판을 올렸고, 도구가 그것을 보지 않는다.** 동결 시험지의 학습 후 M3 실행만 python `3.13.16` 이고 나머지는 모두 `3.13.15` 다. 2026-10-20 과 2026-10-25 사이에 바뀌었다. `judgeft_determinism` 의 환경 비교 항목은 python 을 보지 않고, `judgeft_report` 는 환경을 비교하지 않는다. 새 시험지에서 두 판의 출력이 120문항 모두 같았지만(3-2절), 동결 시험지에서 두 판을 직접 대조하지는 않았다(출처: run_log.md 같은 절). 교체 후보 기준 2와 3의 동결 시험지 값이 이 실행에서 나왔다.
- **관문 (b) 의 학습 시간 어림은 위쪽 어림이 아니었다.** run_log 는 2.7시간을 "위쪽으로 잡은 어림" 이라 적었고 report.md 도 "실제보다 길다" 고 적지만, 실제는 2.97시간이었다. 단계당 시간 70.3초가 실제 평균 73.4초보다 짧았고, 모델을 올리는 시간(첫 단계까지 765초)과 검증 loss 계산 6회를 어림에 넣지 않았다(출처: run_log.md "학습" 절). report.md 의 그 문구는 도구가 만든 것이라 고치지 않았다.
- **관문 (b) 는 갱신이 loss 를 움직이는지 재지 않는다.** 두 단계의 loss 가 같은 것은 첫 단계의 학습률이 warmup 으로 0 이고 LoRA 의 B 행렬이 0 으로 시작하기 때문이다. 첫 단계에서 loss scaling 이 갱신을 건너뛰었어도 같은 값이 나오는데, 노트북이 그 여부를 적지 않아 둘 중 무엇이었는지 가를 수 없다. 이 관문은 메모리, 시간, loss 가 유한한지만 잰다(출처: run_log.md "관문 (b)" 절).
- **M1 은 같은 입력에 같은 점수를 내지 않았다.** 새 시험지에서 실행 2 만 심각한 놓침이 1개 많았다(3-2절). 기준은 M1 에게 가장 좋은 값을 쓰므로 판정에는 영향이 없지만, M1 을 한 번만 돌린 v2 의 동결 시험지 값은 이 변동을 담지 않는다.
- **검색의 근거 유무 판정 값 0.44 가 답할 수 있는 학습용 질문 하나를 버렸다.** `travel-168` 은 가장 가까운 청크의 거리가 0.4534 였다. v2 는 버린 질문이 0개였다(출처: run_log.md "검색 (travel)" 절, v2 결과 2-1절). 질문을 문서를 보고 썼으므로 이 질문도 답할 수 있는 질문이다.
- **검수 불일치가 0 이었다.** v2 에서는 240문항 중 12개였다(v2 결과 2-4절). 같은 읽기가 두 번 겹친 것인지, 이번 시험지가 덜 애매한 것인지는 이 기록으로 가르지 못한다.
- **코랩 채점 시간을 재지 않았다.** 상한만 남았다(7-2절).
- **뉴런을 분야별로 나누지 못한 구간이 있다.** telecom 과 school 은 업로드와 검색을 한 구간에서 해 분야별 값이 없다(7-1절).

### 8-3. 실행 중의 실수와 도구 문제

모두 시험지, 정답 파일, 학습 데이터, 결과 파일에 영향이 없다.

- **채점 노트북이 학습 후 M3 를 돌리려는데 학습 전 M3 설정으로 내려받혔다.** 처음 내려받은 노트북이 `MODEL = 'M3pre'`, 어댑터 해시가 빈 채였다. 이 조합은 학습 전 M3 의 정상 설정이라 노트북이 막지 않는다. 실행 전에 저장소 판과 대조해 고쳤다. 결과 줄마다 `adapter_sha256` 이 적혀 있어, 학습 후 M3 의 결과에 해시가 들어 있음을 확인했다(출처: run_log.md "학습 후 M3 채점과 결정성" 절).
- **관문 (b) 의 첫 시도가 Drive 연결에서 멈췄다.** 권한 창 문제였고 코드를 고치지 않고 다시 실행했다(출처: run_log.md "관문 (b)" 절).
- **`training_log.jsonl` 첫 줄이 관문 (b) 세션의 줄이다.** 같은 Drive 파일에 이어 적혔다(출처: run_log.md "학습" 절).
- **M1 실행 2, 3 의 시험 호출 성공은 한도가 리셋됐다는 증거가 아니다.** 앞 실행이 한도를 다 쓰지 않았기 때문이다(출처: run_log.md "M1 새 시험지 실행 2", "실행 3" 절).

## 9. 재현

- 보고서 재생성: `cd ai-service && .venv/bin/python -m tools.judgeft_report`
- 관문 재확인: `cd ai-service && .venv/bin/python -m tools.judgeft_gate a` (관문 (a)), `... judgeft_gate review` (검수 뒤 조건)
- 결정성 재확인: `cd ai-service && .venv/bin/python -m tools.judgeft_determinism pre`, `... post`
- 시험지 해시 확인: `shasum -a 256 ai-service/testdata/judgeft/cases.jsonl` 이 `60cf9ee8...3461` 과 같아야 한다.
- 학습 데이터 해시 확인: `ai-service/testdata/judgeft/train.sha256`
- 결과 파일: `results/new/`(새 시험지), `results/frozen/`(동결 시험지). 동결 시험지의 M1 과 학습 전 M3 의 v2 실행은 `testdata/judge5v2/results/` 에 있다.
- 어댑터: Drive `MyDrive/alldap_judgeft/adapter/`, SHA-256 `f829d13d...b85c`.

## 10. 다음 단계 후보

학습 후 M3 는 교체 후보이지만, 서비스의 채점 모델을 바꾸는 것은 이 실험의 범위가 아니다(스펙 2-2절). 아래는 결과에서 나오는 후보를 그대로 남긴다. 무엇을 할지는 사용자가 정한다.

- **(가) 학습 후 M3 의 새로 생긴 오류를 읽는다.** 동결 시험지에서 정답 5 인 문항 2개에 1점, ③ 의 놓침 2개, 남은 심각한 놓침(새 시험지 ⑧ 1개, 동결 시험지 ⑧ 1개)이다(6-6절). 출력 원문은 `results/frozen/M3ft_run1.jsonl`, `results/new/M3ft_run1.jsonl` 의 `output` 에 있다. 이 결과 문서에는 넣지 않았다(결과 문서는 보고서 수치만 싣는다).
- **(나) 만드는 방법이 다른 시험지로 확인한다.** 8-2절의 첫 한계다. 예를 들어 실제 답변 생성 모델(llama)이 낸 답변에 정답 점수를 매긴 문항이다. 이것이 서비스에서 바꿀지 판단하는 데 가장 가까운 근거가 된다.
- **(다) 교체를 결정하려면 운영 비용과 구조를 따로 본다.** 학습 후 M3 는 코랩 T4 에서 돌았고, 서비스는 t3.micro 와 Cloudflare 위에 있다. 14B 4비트 모델을 서비스의 평가 경로에서 어디서 돌릴지는 이 실험이 다루지 않았다(AGENTS.md 작업 규칙 7번은 채점 모델의 추론과 학습을 실험 용도로만 열었다).
