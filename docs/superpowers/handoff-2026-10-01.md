## 2. 오늘 닫은 것 (AGENTS.md 와 BACKLOG 에는 아직 안 적었다)

### 2-1. 답변의 번호 인용은 드물다 (후보 ③)

`alldap-fa` 가 로컬 DB 를 읽기 전용으로 셌다. 결정적인 두 사실(생성 프롬프트가 근거에 번호를 붙여 넘긴다, 관리자 채팅 칩에 번호가 있다)은 이 세션이 코드에서 직접 확인했다.

| 대상 | 전체 | 번호 인용 |
|---|---|---|
| `eval_results.generated_answer` (run 11~16, fallback 제외) | 144 | 6 (4.2%) |
| `messages` (assistant, fallback 아님) | 4 | 0 |

- 인용 6건은 매 run 의 q58(징계 종류) 하나다. q58 은 한 근거가 징계를 6가지로, 다른 근거가 4가지로 적은 문항이다. 번호 인용은 근거끼리 말이 다를 때 비교하려고 나오는 것으로 보인다(한 문항이라 가설).
- 정규식: `근거\s*[0-9]+|\[[0-9]+\]`. 오탐 0, 다른 표현(`문서 1`, `1번 근거`)도 0건.
- 생성 프롬프트: `ai-service/app/generator.py:100` 이 `[근거 {i}] (출처: 파일명)` 형식으로 넘긴다. 번호 인용을 막거나 요구하는 규칙은 없다(22~29행).
- 화면: 관리자 채팅만 근거 칩에 번호가 있다(`web/app/(dashboard)/bot/[botId]/chat/page.tsx:336`). 위젯, 로그, 데모는 파일명만 보여준다. 따라서 위젯 사용자에게 "근거 1" 은 가리킬 대상이 없는 문장이다.
- 판단: 빈도가 낮아 제품 문제로 다루지 않고 닫는다. 모순이 많은 고객 코퍼스에서는 흔해질 수 있지만 이 DB 로는 가를 수 없다.

### 2-2. 맨 앞 끼우기의 순수한 자리 효과는 34건 중 1건 (후보 ①)

새로 돌리지 않고 기존 결과로 답했다. 2-1 에서 번호를 인용하는 답변이 q58 뿐이므로, 주입 탐침 대상 38건 중 q58 4건을 빼면 34건이 모두 번호를 인용하지 않는 답변이다. 그 34건에서 `near+1@front` 하락은 q70 1건뿐이었다. 즉 번호 밀림을 뺀 자리 효과는 34건 중 1건이다. 뉴런을 쓰지 않았다.

### 2-3. 기록해야 할 자리

`AGENTS.md` 의 "무관한 청크 주입 탐침 (2026-09-26)" 절 끝과 `docs/BACKLOG.md` §5 의 후속 ①, ③ 행에 위 두 결과를 적고 닫아야 한다. 문서만 고치는 일이라 `main` 에 바로 올려도 되는 범주다. 오늘은 파인튜닝 설계로 넘어가느라 적지 않았다.

## 3. 파인튜닝 설계의 결정 (사용자와 합의한 순서대로)

| 결정 | 이유 | 기각한 대안 |
|---|---|---|
| 목적은 리랭커 파인튜닝 전후 수치 비교 | 사용자가 측정 트랙을 여기까지 끌고 가기로 함. 출발점(리랭커가 정답을 밀어낸 실패)에서 멀어진 측정 사슬을 다시 목표에 잇는다 | 측정 트랙 종료, 제품 작업(위젯 색상 등) |
| 대표 지표는 상위 5개 진입률, 전체충실성은 보조 | 리랭커가 바꾸는 것은 순서뿐이다. 채점자 흔들림(2026-09-18)이 끼지 않고 뉴런이 거의 안 든다 | 전체충실성 대표, 둘 동등 |
| 문서 단위로 학습용과 시험용을 가름 (처음 보는 문서) | 고객마다 문서가 다르므로 한 번 학습시켜 모든 고객에게 써야 한다 (사용자가 짚음) | 청크 단위 분할(고객마다 따로 학습하는 구조가 됨), 질문 문장만 바꾸기(외운 것과 구분 불가) |
| 양쪽에 헷갈릴 짝이 둘 이상 남게 가름 | 짝이 하나뿐이면 대상을 안 읽어도 맞혀 전후 차이가 안 드러난다 (사용자가 "묶음째로" 규칙의 오류를 짚어 고침) | 헷갈림 묶음을 통째로 한쪽에 보내기 |
| 분할안 A (누출 0 우선) | 안 B 는 기존 문항 5개를 재사용하지만 5개로는 부족하고, `02_계약직` 이 `01_정규직` 을 참조해 시험 봇에 답이 없는 문제가 생긴다 | 안 B |
| 학습은 코랩 | 사용자 결정 | 로컬 M4 Pro (가능은 함) |
| 모든 문제를 Claude 가 씀, 말투 다섯 가지 | 한 번만 학습하므로 자동 생성 불필요. Gemini 하루 20회 한도. 자동 생성 결함 전례 | Gemini 생성기로 시험 문제 일부(검증용 20개). 사용자가 "그냥 너가 다 만들어" 로 기각. 한계로 스펙 §9 에 적음 |
| 전후 기준은 로컬 fp32 원본(B) | 실행 환경이 같아야 차이가 파인튜닝 하나로만 생긴다 | Cloudflare 리랭커 |
| 판정은 좋아짐, 나빠짐 문제 수의 양측 부호 검정 (p < 0.05) | 로컬 측정이 결정적이라 반복 평균이 무의미하다. 불확실성은 문제 선택에서 온다 | 평균 차이만 보기 |
| 학습 전 관문: 고칠 수 있는데 5위 밖인 문제가 4분의 1 이상 | 고칠 자리 없는 시험(지금 평가셋의 문제)을 학습 전에 막는다 | 관문 없이 학습 |
| 예비 시험 문제를 학습 데이터보다 먼저 씀 | 파인튜닝이 효과 없을 때 "학습 실패" 와 "일반화 실패" 를 가르려면, 그 정답 청크가 학습에 안 쓰였어야 한다 | 실패한 뒤에 쓰기 (누출) |
| 생성, 채점 셀프호스팅은 이번에 안 함 | AGENTS.md 작업 규칙 7번. 끝난 뒤 따로 판단하기로 사용자와 약속 | 이번에 같이 |

## 7. 다음 사람이 밟을 함정

- **메인 폴더에서 브랜치를 바꾸지 말 것.** 여러 세션이 같은 폴더를 쓴다. 구현은 워크트리에서.
- **봇 1번을 건드리지 말 것.** `eval_set load --replace --bot-id 1` 은 `eval_results` 를 CASCADE 로 지운다. 새 문제는 새 봇(시험용 봇)에만 적재한다.
- **스키마는 Spring 이 기동해야 생긴다.** 봇 생성과 문서 업로드에는 `docker compose up -d` → `api` → `ai-service` 순서로 셋 다 필요하다. 오늘 `alldap-fa` 가 Docker 데몬이 꺼져 있어 Docker Desktop 과 DB 를 띄웠다. 지금도 떠 있을 수 있다.
- **업로드는 임베딩을 부른다.** Cloudflare 임베딩 뉴런은 아주 작다(평가 1회에 0.4). 걱정할 수준은 아니지만 0 은 아니다.
- **로컬 리랭커는 `requirements-lab.txt` 설치가 필요하다.** 원본 모델 산출물(`models/` 의 `local`, `local_int8`)은 2026-09-17 에 만든 것이 있어야 한다. 없으면 `python -m app.export_reranker`. 이미 있는 산출물은 `--force` 없이 덮지 않는다(대조군 보존).
- **`split.json` 의 근거 표는 손으로 센 것이다.** 한두 칸 틀릴 수 있다. 시험 문제를 쓰다 규칙 위반(시험 봇 안에 답이 없는 문제, 대상 불일치)을 발견하면 분할을 고치지 말고 그 문제를 버린다. 분할을 바꾸면 이미 쓴 문제 전체를 다시 봐야 한다.
- **`04_파견` 의 `SEC-002` 규정은 `10_보안`(학습용)에 기댄다.** 그 규정을 묻는 시험 문제를 쓰지 말 것 (스펙 §4-4 규칙 3).
- **시험 문제 성적으로 학습 설정을 고르지 말 것.** 에폭 선택은 연습 문제 20% 검증용으로 한다 (스펙 §6-2).
- **Gemini 는 이번 실험에서 쓰지 않는다.** 문제는 전부 Claude 가 쓴다.

## 8. 안 한 것 · 모르는 것 (정직하게)

- **스펙은 사용자가 파일로 읽고 승인하지 않았다.** 설계 내용은 대화에서 섹션별로 승인받았다.
- **학습 시간은 재지 않았다.** 수 분에서 수십 분은 추정이다.
- **분할이 관문(4분의 1)을 통과할지 모른다.** 시험용 봇에 문서가 9개 + 일반 문서 일부뿐이라 후보 20개 안에 정답이 들어오기 쉽다. 그것이 고칠 자리를 늘릴지 줄일지는 재 봐야 안다.
- **2-2 의 34건 중 1건은 기존 결과를 다시 읽은 추론이다.** 새로 측정하지 않았다.
- **`docs/superpowers/specs/2026-09-26-inject-probe-design.plain.md` 는 여전히 처리하지 않았다** (앞 핸드오프 §8). 원래부터 있던 미커밋 파일(`docs/blog-draft*.md`, `docs/cover/`, `docs/icons/`)도 그대로다.

## 9. 오늘 사용자와 정한 작업 방식 (메모리에 저장함)

- **당분간 로컬에서만 개발한다.** 운영 데이터와 배포는 선택지로 올리지 않는다.
- **작업을 제안하거나 시작할 때 "왜 하는가" 를 대화에서 먼저 말한다.** 문서에 규칙으로 적지는 않는다.
- **파인튜닝이 끝나면 채점, 생성 모델 셀프호스팅을 다시 꺼낸다.** 판단 재료: 70B 는 4비트로도 약 40GB 라 M4 Pro 24GB 에 안 들어간다. 작은 모델은 NO_ANSWER 준수가 위험하다(`qwen3-30b` 탈락 전례). 채점 쪽은 사람 라벨 44건으로 새 채점자를 바로 검증할 수 있어 더 현실적이다.
- **설명은 쉽게.** 오늘 사용자가 세 번 "무슨 말이지?" 를 물었다. 비유와 구체 예시(객관식 보기, 도서관 사서)로 다시 설명했을 때 통했다.
