## 1. §7-① 운영 `.env`: 결론이 "값이 맞다" 가 아니다

**검색 설정 변수 넷(`RERANKER_ENABLED` · `HYBRID_ENABLED` · `RERANK_FUSION` ·
`ANSWERABLE_MAX_DISTANCE`)이 운영에 아예 없다.** 그래서 코드 기본값(`True`/`True`/`False`/`0.44`)이
그대로 적용된다. 즉 운영 봇은 리랭커+하이브리드 ON 으로 돌고 있고 회당 오답 0.00 이다.

증거가 네 겹이다. ① `.env.prod` 에 해당 키 0건 ② `docker-compose.prod.yml` 에 `env_file:` 이
한 줄도 없고 `environment:` 는 6개만 나열한다 = **적어 넣어도 컨테이너에 안 간다**
③ `docker exec ... env` 전체 키에 넷 다 없음 ④ 컨테이너 안에 `.env` 파일 자체가 없다.

→ **`.env.example` 의 틀린 `RERANKER_ENABLED=false` 는 운영에 도달한 적이 없다.**
운영은 `.env.prod` 계열을 쓰지 `ai-service/.env.example` 을 쓰지 않는다.

> ⚠️ **한계**: 배포 이미지 안의 `config.py` 를 직접 읽지는 못했다(권한 분류기가 `docker exec` 의
> 파일 읽기를 거부, `env` · `ls` 는 통과). 기본값 넷은 **저장소 소스 + 이미지 빌드 시각**으로
> 뒷받침한 논증이다.

🔴 **부수 발견: 운영에서 검색 설정을 껐다 켤 방법이 지금은 없다.** `.env.prod` 에도 compose 에도
통로가 없어 재배포로 코드 기본값을 바꾸는 것뿐이다. 지금 기본값이 옳아 급하지 않지만,
"운영에서 껐다 켜며 비교" 를 하려면 `environment:` 에 통로를 내는 별도 조각이 필요하다.

**덤으로 확인한 것: 운영 CORS 도 정상이다.** `.env.prod` 는 `all-dap.vercel.app`(하이픈 있음)이고
틀린 것은 `.env.prod.example` 뿐이었다(`136670c` 로 고쳤다).

> 🔴 **"돌고 있으니 맞을 것" 이 추측이라는 것보다 더 중요한 것**: 이 건에서는 **돌고 있다는 것
> 자체가 근거가 되지도 않았다.** 오타였다면 증상은 "서비스가 죽는다" 가 아니라 **"브라우저에서
> 나가는 API 호출만 CORS 로 막힌다"** 였을 것이고, `curl` 기반 헬스체크·배포 검증은 Origin 을
> 안 보내니 **전부 초록불**이었을 것이다. 값을 직접 봐야 했다.

## 2. §7-③ 파서 경계 검사 (PR #121, 머지됨)

`promtext.py` 의 `parse_prom_counter` 에 경계 검사 한 줄. `startswith(name)` 뒤가 `{` 또는 공백일 때만
일치로 인정한다. `continue` 라서 조기 반환 성질은 안 건드렸다.

**고치기 전에 검사가 실제로 실패하는지부터 봤다.** `s3_check` 종료 1(노출 순 통과 · 뒤집은 순 실패) ·
`s4_check` 종료 1. **노출 순만 통과하는 것이 논지 그대로다** = 통과하던 이유가 파서가 옳아서가
아니라 prometheus-metrics 의 알파벳 순 덕이었다.

**값이 안 바뀐다는 대조가 이 PR 의 근거다.** 실제 캡처(`results/S4-*-prom-after.txt`)에 두 드라이버가
내는 조회 전부를 노출 순·뒤집은 순으로 물어 **84건 중 달라진 것 0건.** 그래서 측정 7판을 다시
돌리지 않고 정당화된다. `results/` 는 한 글자도 안 고쳤다.

> 🔴 **정정: "두 드라이버가 내는 조회 전부" 라는 범위 서술이 부정확했다.**
> 84 = **S4 조회 14종 × 캡처 3건 × 순서 2가지** 다. 대조에 쓴 캡처가
> `results/S4-*-prom-after.txt` **3건뿐**이고, `results/` 에 **S3 의 prometheus 노출
> 원문은 파일로 없다**(S3 는 `*-context.json` 에 값만 남겼다. `ls results/ | grep prom`
> 으로 확인했다). 즉 **S3 노출 원문으로 파서를 대조한 사람은 여전히 없다.**
>
> PR #128 이 조회를 19종(114 = 19 × 3 × 2)으로 넓혔지만 그것도 같은 한계를 갖는다:
> 더한 S3 조회 5종은 **S4 캡처에 시계열이 없어 양쪽 파서가 다 `None` 을 돌려준다.**
> "0건 달라졌다" 는 참이지만 그 5종에 대해서는 <아무것도 안 물어본 것>과 구별되지 않는다.
> **"몇 건을 대조했다" 와 "무엇에 대고 대조했다" 는 다른 사실이다.**

회귀 검사를 두 자체 점검의 **실제로 도는 자리**에 서로 다른 각도로 넣었다.
s3 은 라벨 없는 게이지로 **"줄 순서에 기대지 않는다"** 를 증명하고, s4 는 타이머의 `_count`·`_sum`
공통 접두사(`alldap_ai_call_seconds`, **노출에 없는 이름**)로 **라벨 조건이 있어도 못 막는다**는 것을 보인다.

🔴 **남긴 것: NaN 분리.** `float('NaN')` 이 실패하지 않고 `nan` 으로 통과해 **"계측이 살아 있다" 와
"계측이 죽어 NaN 이다" 를 뭉갠다.** 반환 타입과 호출부 분기가 늘어 "값이 안 바뀐다" 근거가 깨지므로
별도 판단이 필요하다. PR 본문 한계 칸에 알면서 남겼다고 적었다.

### ⓐ 🔴 내가 분배한 전제가 네 번 뒤집혔다. 네 번 다 세션이 파일을 직접 열어서 뒤집었다

| "`.env.example` 에 없는 키가 안내돼 있다" | `.env.example` 은 **이미 정확했다.** 틀린 것은 README 안내 한쪽뿐 |
| "`README:69`(§11.3)와 `AGENTS.md`(§11.2)가 어긋난다" | **어긋남이 아니다.** 원칙은 §11.2 에 있고 README 는 <그 충돌이 기록된 자리>(§11.3)를 가리킨다. **서로 다른 것을 가리키고 각자 맞다** |
| "종단 기록이 없다" | 과한 단언. 위 §4 |

**교훈: 분배 지시에 넣은 <사실>도 근거를 붙여 보내고, 세션이 뒤집을 수 있게 여지를 남길 것.**
앞 세션이 "조회 이름을 핸드오프에서 가져와서" 파서 충돌을 놓친 것과 같은 부류다.
세 번째는 **내가 반대 방향으로 뭉갤 뻔한 것**이다(서로 다른 두 사실을 하나의 오류로).

### ⓑ 주제로 나누면 파일이 겹친다. 파일로 나눠야 한다

원래 주제별 4갈래를 만들었는데 `AGENTS.md` 와 `README.md` 가 여러 갈래에 걸렸다.
**파일 소유권으로 다시 갈라 분배했고 충돌 0건이었다.** 앞 세션은 주제로 나눴다가 충돌했다.

### ⓒ 지시 범위를 넘은 보고 셋을 승인했다. 셋 다 넘은 것이 맞았다

- api/README 타임아웃 표 (문구만 빼면 **틀린 표가 확정된 사실처럼** 남는다)
- 같은 절의 "재시도해도 되는 것: GET" 코드블록
- PRD §11.2 Flyway 행 모순

**공통점: "지시한 문구를 빼면 주변이 거짓이 되는" 자리였다.** 지시를 글자대로만 따르면
낡은 문장 하나를 지우고 **더 틀린 문서**를 남기게 된다.

### ⓓ em dash 가 다섯 브랜치 중 셋에 들어갔다

한 세션이 자기 커밋에서 발견해 수습하고(`85a8d5f`) **다른 세션들도 확인하라고 알렸다.**
훑어보니 **진짜 대상은 3곳**이고 나머지는 전부 표 빈 칸 `| — |` 였다(그건 두는 것이 맞다).
그중 하나는 원래 있던 줄인데 **확장자를 고치느라 diff 에 추가 줄로 잡힌 것**이었다.
`^+` 는 "새로 쓴 줄" 이 아니라 **"이 PR 이 손댄 줄"** 이다. 손댄 이상 규칙은 적용된다.

### ⓔ 세션이 자기 실수를 정확히 귀속했다

PRD 세션이 *"제 원래 보고가 '못 찾았습니다' 였는데 첫 커밋에서 제가 그걸 '미검증' 으로 단단하게
옮겼습니다. 골자만의 문제가 아니라 제가 쓰면서 한 번 더 조인 것입니다"* 라고 적었다.
**자기가 §11.2/§11.3 에서 갈라낸 것과 같은 모양의 실수를 자기 문장 안에서 했다는 것까지 짚었다.**
`evalrun.py` 안에서 그 규칙이 다시 뚫린 것과 같은 구조다.
